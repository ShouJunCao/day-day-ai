10.3 框架对比：LangGraph / AutoGen / CrewAI / OpenAI Agents SDK / Dify

模块十：AI Agent 开发 预计学习：50 分钟

学习目标

  • 了解五大主流 Agent 框架的核心差异和适用场景
  • 掌握框架选择的关键评估维度
  • 学会根据项目需求选择最合适的框架
  • 能够基于 LLM 构建智能框架推荐助手

一、框架全景对比

在 AI Agent 开发领域，目前主流的框架有五种：LangGraph（LangChain 生态）、AutoGen（Microsoft）、CrewAI、OpenAI Agents SDK 和 Dify。这些框架各有侧重，覆盖了从低代码可视化到高度编程控制的不同需求层次。理解这些框架的差异，是选择合适工具链的第一步。

从架构理念来看，LangGraph 追求极致的灵活性和控制力，适合需要精细设计工作流的复杂应用；AutoGen 强调多 Agent 对话协作，适合代码生成和讨论场景；CrewAI 关注角色分工和任务编排，适合团队化 Agent 开发；OpenAI Agents SDK 追求轻量简洁，适合快速集成到现有 OpenAI 应用中；Dify 则面向非技术用户，通过可视化编排降低了 Agent 开发的门槛。

选择框架时需要考虑多个维度：是否需要多 Agent 协作、是否需要图编排能力、团队的技术水平、项目的时间要求、对定制化的需求程度等。没有一个框架在所有维度上都是最优的，关键在于找到最适合当前项目需求的平衡点。

二、LangGraph

LangGraph 是 LangChain 生态中的图编排框架，基于有向图（Directed Graph）概念构建 Agent 工作流。它允许开发者定义复杂的状态机和循环逻辑，是五个框架中控制力最强、灵活度最高的选择。LangGraph 的核心优势在于：支持自定义状态管理、支持循环和条件分支、支持多 Agent 协作、与 LangChain 生态无缝集成。

使用 LangGraph 需要定义状态结构（State）、节点函数（Node）和边（Edge），然后编译成可执行的应用。这种编程模型虽然灵活，但也带来了较高的学习成本。开发者需要理解状态机的概念，并熟练掌握图编排的语法。

2.1 LangGraph 代码示例

Python（LangGraph 基本用法）
from langgraph.graph import StateGraph
from typing import TypedDict

# 1. 定义状态
class AgentState(TypedDict):
    messages: list
    result: str

# 2. 定义节点函数
def research_node(state):
    return {"messages": ["搜索中..."]}

def write_node(state):
    return {"result": "撰写完成"}

# 3. 构建图
graph = StateGraph(AgentState)
graph.add_node("research", research_node)
graph.add_node("write", write_node)
graph.add_edge("research", "write")
app = graph.compile()

# 4. 执行
result = app.invoke({"messages": ["分析数据"]})

三、AutoGen

AutoGen 由 Microsoft 开发，是一个基于对话的多 Agent 框架。它的核心理念是：让多个 Agent 通过对话协作来完成复杂任务。AutoGen 特别擅长代码生成和评审场景，因为不同的 Agent 可以扮演不同的角色（如程序员、评审员、测试员），通过对话迭代改进代码。

AutoGen 的 API 设计简洁，主要通过 ConversableAgent 和 GroupChat 两个核心类来实现。开发者只需创建 Agent 实例，定义它们的角色和系统提示词，然后启动对话即可。AutoGen 的优势在于对话自然、代码生成能力强，但对话控制相对复杂，需要仔细调优以避免无限循环。

3.1 AutoGen 代码示例

Python（AutoGen 基本用法）
from autogen import ConversableAgent

# 1. 创建 Agent
user_proxy = ConversableAgent(
    name="User",
    llm_config=False
)
assistant = ConversableAgent(
    name="Assistant",
    llm_config={"model": "gpt-4"}
)

# 2. 启动对话
user_proxy.initiate_chat(
    assistant,
    message="帮我写一个爬虫程序"
)

四、CrewAI

CrewAI 是一个面向团队协作的 Agent 框架，采用"角色-任务-团队"三层抽象模型。开发者定义不同的 Agent 角色（如研究员、作家、编辑），为每个角色分配具体任务，然后将它们组合成一个 Crew（团队）来执行。CrewAI 的 API 设计非常简洁，是五个框架中最容易上手的之一。

CrewAI 适合快速构建角色分工明确的 Agent 应用，如内容创作流水线（研究 → 撰写 → 编辑 → 发布）、数据分析流程（收集 → 分析 → 报告）等。它的局限性在于对复杂工作流的支持有限，当需要精细控制执行流程时，可能需要选择 LangGraph。

4.1 CrewAI 代码示例

Python（CrewAI 基本用法）
from crewai import Agent, Task, Crew

# 1. 定义 Agent
researcher = Agent(
    role="研究员",
    goal="深入研究技术问题",
    backstory="你是资深技术研究员"
)
writer = Agent(
    role="作家",
    goal="撰写清晰的技术文章",
    backstory="你是经验丰富的技术作家"
)

# 2. 定义任务
research_task = Task(
    description="研究 ReAct 框架",
    agent=researcher
)
write_task = Task(
    description="根据研究撰写文章",
    agent=writer
)

# 3. 创建 Crew 并执行
crew = Crew(agents=[researcher, writer], tasks=[research_task, write_task])
result = crew.kickoff()

五、OpenAI Agents SDK

OpenAI Agents SDK 是 OpenAI 官方推出的轻量级 Agent 开发框架。它基于 OpenAI 的 Function Calling 能力，提供了简洁的 API 来构建 Agent 应用。与其他框架相比，OpenAI Agents SDK 的最大优势是：轻量简单、类型安全、与 OpenAI 生态深度集成。

OpenAI Agents SDK 适合构建轻量级的 Agent 应用，特别是那些只需要单个 Agent 配合少量工具的场景。它的局限性在于：目前仅支持 OpenAI 模型、多 Agent 支持较弱、复杂工作流编排能力有限。如果你的项目主要使用 OpenAI 模型且需求相对简单，这是一个不错的选择。

5.1 OpenAI Agents SDK 代码示例

Python（OpenAI Agents SDK 基本用法）
from agents import Agent, Runner, function_tool

@function_tool
def search(query: str) -> str:
    return f"搜索结果: {query}"

agent = Agent(
    name="助手",
    instructions="你是一个有用的助手",
    tools=[search]
)

result = await Runner.run(agent, "查询天气")
print(result.final_output)

六、Dify

Dify 是一个开源的 LLMOps 平台，提供了可视化的 Agent 编排能力。与其他框架不同，Dify 主要面向非技术用户，通过拖拽式的工作流编辑器，让用户无需编程即可构建复杂的 Agent 应用。Dify 支持多种模型接入、可视化调试、API 发布、监控分析等功能，是一个开箱即用的 Agent 开发和部署平台。

Dify 适合以下场景：团队中缺乏专业开发人员、需要快速原型验证、希望降低 Agent 开发门槛、需要一个完整的 LLMOps 平台而不仅仅是开发框架。Dify 的局限性在于：定制化能力有限、高级功能需要付费、对复杂编程逻辑的支持不如代码框架灵活。

6.1 Dify 使用方式

Python（Dify API 调用）
# Dify 使用方式：
# 1. 在可视化界面拖拽组件构建工作流
# 2. 配置 LLM 节点、工具节点、条件节点
# 3. 通过 API 调用已部署的工作流

import requests

response = requests.post(
    "https://api.dify.ai/v1/workflows/run",
    json={"inputs": {"query": "分析数据"}},
    headers={"Authorization": "Bearer YOUR_API_KEY"}
)
result = response.json()

八、基于 LLM 的框架推荐助手

在实际项目中，框架选择往往涉及多个维度的权衡。为了帮助开发者做出更明智的选择，我们可以构建一个基于 LLM 的框架推荐助手。这个助手接收用户的自然语言需求描述，结合框架特性数据，通过大模型推理给出最适合的框架推荐。

推荐助手的工作流程包括：需求解析（理解用户的项目需求和技术背景）、框架匹配（根据需求特征匹配框架特性）、LLM 推理（调用大模型进行综合分析）、结果输出（给出推荐框架、推荐理由和注意事项）。

8.1 推荐助手实现

Python（框架推荐助手）
class FrameworkAdvisor:
    """基于 LLM 的框架选择建议助手"""
    
    PROMPT_TEMPLATE = """你是一个 AI 开发专家，擅长选择合适的 Agent 框架。
请根据用户的需求，从以下框架中选择最合适的一个。

可选框架：
- LangGraph: 复杂工作流，精细控制
- AutoGen: 多 Agent 对话，代码生成
- CrewAI: 角色分工，快速构建
- OpenAI Agents SDK: 轻量简洁
- Dify: 可视化编排，开箱即用

用户需求：
{requirements}

请输出：
推荐框架: <框架名称>
推荐理由: <详细理由>
替代方案: <次优选择>
注意事项: <使用建议>"""

    def recommend(self, requirements: str):
        """调用 LLM 进行框架推荐"""
        prompt = self.PROMPT_TEMPLATE.format(
            requirements=requirements
        )
        response = client.chat.completions.create(
            model="qwen3.7-max",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.3,
        )
        return response.choices[0].message.content
💡 实战建议

在选择 Agent 框架时，建议先在每个候选框架上做一个简单的原型验证（Proof of Concept），评估其实际开发体验。不要仅凭文档和教程做决定，实际的编码体验往往能揭示文档中看不到的问题。同时，考虑团队的长期维护能力——选择一个团队能够熟练掌握的框架，比选择一个功能最全但难以掌握的框架更为重要。

九、小结

五大 Agent 框架各有特色，覆盖了从低代码可视化到高度编程控制的不同需求层次。LangGraph 适合需要精细控制的复杂工作流，AutoGen 擅长多 Agent 对话协作，CrewAI 以简洁的 API 快速构建角色分工团队，OpenAI Agents SDK 为轻量级场景提供简洁方案，Dify 则降低了非技术用户的使用门槛。理解各框架的定位和差异，有助于在项目初期做出明智的技术选型决策。
