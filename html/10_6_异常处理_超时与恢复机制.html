10.6 异常处理、超时与恢复机制

模块十：AI Agent 开发 预计学习：45 分钟

  • 理解 Agent 执行中常见的异常类型和产生原因
  • 掌握超时控制、重试机制和熔断器的实现方法
  • 学会设计恢复策略以应对不同类型的错误
  • 能够构建鲁棒性强的生产级 Agent 系统

一、异常处理概述

在 Agent 的实际运行过程中，异常情况是不可避免的。常见的异常类型包括：网络异常（连接超时、DNS 解析失败）、API 异常（限流、认证失败、服务不可用）、工具异常（权限不足、资源不存在）、LLM 异常（模型超时、输出格式错误）。这些异常如果处理不当，会导致 Agent 执行中断或产生错误结果。

完善的异常处理机制是生产级 Agent 系统的必备条件。它不仅能够提高系统的可用性，还能在出现问题时提供清晰的错误信息，便于快速定位和修复。在设计异常处理机制时，需要考虑以下几个原则：快速失败（尽快识别并报告错误）、优雅降级（在部分功能不可用时仍能提供基本服务）、自动恢复（对临时性错误进行自动重试）、可观测性（记录详细的错误信息便于分析）。

在 Agent 开发中，异常处理应该贯穿整个执行链路：从工具调用层到 Agent 循环层，再到任务调度层，每一层都应该有相应的异常处理逻辑。通过分层处理，可以确保异常在不同层级得到恰当的响应，既不会过度处理简单错误，也不会遗漏严重问题。

二、超时控制

超时控制是防止 Agent 无限期等待的关键机制。在 Agent 执行过程中，任何一步操作都可能因为网络问题、服务不可用等原因而长时间阻塞。如果没有超时控制，Agent 可能会陷入无限等待，浪费系统资源并影响用户体验。

超时控制应该设置在多个层级：工具调用层（单个工具执行的超时时间）、Agent 循环层（整个循环的超时时间）、任务调度层（整个任务的超时时间）。通过多层超时控制，可以在不同粒度上保护系统免受长时间阻塞的影响。

2.1 超时控制器实现

Python（超时控制器）
import time

class TimeoutController:
    """超时控制器"""
    
    def __init__(self, timeout_seconds=30.0):
        self.timeout = timeout_seconds
        self.start_time = None
    
    def __enter__(self):
        self.start_time = time.time()
        return self
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        elapsed = time.time() - self.start_time
        if elapsed > self.timeout:
            raise AgentTimeoutError(
                f"执行超时: {elapsed:.1f}s > {self.timeout}s"
            )
        return False
    
    def check_timeout(self):
        """在循环中主动检查超时"""
        if self.start_time is None:
            return False
        elapsed = time.time() - self.start_time
        if elapsed > self.timeout:
            raise AgentTimeoutError(
                f"执行超时: {elapsed:.1f}s > {self.timeout}s"
            )
        return False

# 使用示例
with TimeoutController(timeout_seconds=30.0) as tc:
    for step in plan:
        execute_step(step)
        tc.check_timeout()

三、重试机制

重试机制是处理临时性错误的常用策略。许多错误（如网络抖动、服务暂时不可用、限流）都是暂时性的，通过重试可以自动恢复。然而，重试策略的设计需要谨慎：过少的重试次数可能导致可恢复的错误被误判为永久错误，过多的重试次数则会浪费时间和资源。

推荐的重试策略是指数退避（Exponential Backoff），即每次重试的等待时间呈指数增长。这种策略既可以给服务足够的恢复时间，又可以避免在服务器高负载时进一步加重负担。同时，应该设置最大重试次数和总超时时间，防止无限重试。

3.1 异常处理器实现

Python（异常处理器）
class ExceptionHandler:
    """异常处理器"""
    
    def __init__(self, exception_type, max_retries=3,
                 retry_delay=1.0, fallback_action=None):
        self.exception_type = exception_type
        self.max_retries = max_retries
        self.retry_delay = retry_delay
        self.fallback_action = fallback_action

    def handle(self, func, *args, **kwargs):
        """执行带异常处理的函数"""
        last_error = None
        
        for attempt in range(self.max_retries + 1):
            try:
                return func(*args, **kwargs)
            except self.exception_type as e:
                last_error = e
                if attempt < self.max_retries:
                    # 指数退避
                    delay = self.retry_delay * (2 ** attempt)
                    time.sleep(delay)
                else:
                    print("重试次数耗尽")
        
        # 回退逻辑
        if self.fallback_action:
            return self.fallback_action(last_error)
        
        raise last_error

四、熔断器

熔断器（Circuit Breaker）是一种保护机制，用于防止系统在服务持续不可用时反复尝试调用，从而避免资源浪费和级联故障。熔断器的工作模式类似于电路中的保险丝：当错误次数超过阈值时，熔断器"跳闸"（打开），拒绝后续请求；经过一段时间的冷却后，熔断器"半开"，允许试探性请求；如果试探成功，熔断器"闭合"，恢复正常。

熔断器有三种状态：闭合（Closed，正常执行）、打开（Open，拒绝请求）、半开（Half-Open，试探性执行）。状态转换的规则是：闭合状态下，连续失败次数超过阈值则转为打开；打开状态下，经过冷却期后转为半开；半开状态下，如果试探请求成功则转为闭合，如果失败则转回打开。

4.1 熔断器实现

Python（熔断器）
class CircuitBreaker:
    """熔断器"""
    
    def __init__(self, failure_threshold=5,
                 recovery_timeout=60.0):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.state = "closed"
        self.failure_count = 0
        self.last_failure_time = None

    def call(self, func, *args, **kwargs):
        if self.state == "open":
            if (time.time() - self.last_failure_time 
                > self.recovery_timeout):
                self.state = "half_open"
            else:
                raise Error("熔断器已打开")
        
        try:
            result = func(*args, **kwargs)
            self._on_success()
            return result
        except Exception as e:
            self._on_failure()
            raise e

五、恢复策略

恢复策略定义了 Agent 在遇到不同类型错误时应该采取的应对措施。一个好的恢复策略应该能够根据错误的性质选择合适的处理方式，既不会过度处理简单错误，也不会对严重错误掉以轻心。在设计恢复策略时，需要考虑错误的可恢复性、任务的关键程度、系统的整体状态等多个因素。

常见的恢复策略包括：重试（对临时性错误进行重复尝试）、降级（使用备用方案或简化功能）、跳过（忽略非关键错误继续执行）、中止（遇到严重错误时停止执行）、回退（恢复到之前的稳定状态）。选择合适的恢复策略需要综合考虑错误类型、任务重要性和系统状态等因素。在实际应用中，建议为每种错误类型定义明确的恢复策略，并通过配置化的方式管理这些策略，便于后续的调整和优化。

5.1 恢复策略映射

错误类型恢复策略说明重试次数

六、综合异常处理框架

将超时控制、重试机制、熔断器和恢复策略组合在一起，可以构建一个完善的异常处理框架。这个框架能够为 Agent 的执行提供全方位的保护，确保在各种异常情况下都能做出恰当的响应。通过分层设计，每一层专注于特定类型的异常处理，既避免了功能重叠，又确保了覆盖的全面性。

综合框架的设计要点包括：分层处理（不同层级处理不同类型的异常）、策略组合（根据错误类型组合使用多种恢复策略）、状态跟踪（记录错误历史和恢复效果）、可配置性（通过配置文件调整各项参数）。通过这些设计，可以构建出既能应对常见错误又能处理极端情况的鲁棒系统。在实际部署时，建议将异常处理框架与监控告警系统集成，实现自动化的异常检测和响应。

6.1 综合框架示例

Python（综合异常处理）
class RobustAgent:
    """鲁棒 Agent"""
    
    def __init__(self):
        self.timeout = TimeoutController(30.0)
        self.handler = ExceptionHandler(
            exception_type=Exception,
            max_retries=3,
            retry_delay=1.0
        )
        self.breaker = CircuitBreaker(
            failure_threshold=5,
            recovery_timeout=60.0
        )
    
    def execute_with_protection(self, goal):
        """带保护的执行"""
        with self.timeout:
            # 熔断器保护
            result = self.breaker.call(
                self.handler.handle,
                self._execute, goal
            )
            return result
    
    def _execute(self, goal):
        """实际执行逻辑"""
        # Agent 执行代码
        pass
💡 实战建议

在生产环境中，建议为每个异常处理组件设置合理的参数：超时时间根据网络延迟和任务复杂度调整（通常 30-120 秒），重试次数根据错误类型设置（网络错误 3-5 次，业务错误 1-2 次），熔断阈值根据历史错误率设定（通常 5-10 次连续失败）。同时，建议将所有异常处理和恢复操作记录到日志中，便于后续分析和优化。

七、小结

异常处理、超时控制和恢复机制是构建鲁棒 Agent 系统的核心要素。通过合理组合超时控制器、异常处理器、熔断器和恢复策略，可以确保 Agent 在面对各种异常情况时都能做出恰当的响应。这些机制不仅能够提高系统的可用性和稳定性，还能在出现问题时提供清晰的错误信息，便于快速定位和修复。
