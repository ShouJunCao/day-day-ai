6.1 RAG 整体流程与核心挑战

模块六：RAG 核心架构 预计学习：50 分钟

学习目标

  • 理解 RAG（检索增强生成）的整体架构和工作流程
  • 掌握 RAG 与传统问答系统的本质区别
  • 识别 RAG 系统中的核心组件及其职责
  • 了解 RAG 面临的核心挑战：幻觉、召回质量、上下文窗口限制等

一、什么是 RAG？

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将外部知识检索与大语言模型生成能力相结合的技术范式。它的核心思想是：在让大语言模型回答问题之前，先从外部知识库中检索相关信息，将检索结果作为上下文提供给模型。这样，模型可以基于最新的、准确的外部知识来生成回答，而不是仅依赖训练数据中的过期信息。

RAG 的出现解决了一个根本性问题：大语言模型的训练数据有截止时间，且模型参数是静态的，无法自动获取新知识。通过 RAG，我们可以在不重新训练模型的情况下，让模型"知道"最新的信息——只需要更新外部知识库即可。

举个例子：如果你的知识库中包含了 2024 年的最新政策文件，RAG 系统可以让大语言模型回答关于这些政策的问题，即使模型的训练数据截止到 2023 年。这就是 RAG 的核心价值——让静态模型具备动态知识访问能力。

二、RAG vs 传统问答系统

传统的问答系统通常依赖关键词匹配或预定义的规则来检索答案，而 RAG 系统则完全不同。下面是两者的核心差异对比：

维度传统问答系统RAG 系统
知识来源预定义知识库或规则动态外部文档库
理解能力关键词匹配，无语义理解基于 LLM 的语义理解
知识更新需要人工更新知识库更新文档库即可
回答生成固定模板或预定义答案LLM 动态生成
幻觉问题不存在（固定答案）可能存在（需控制）
适用场景FAQ、简单客服复杂问答、知识检索

RAG 的核心优势在于：它结合了检索系统的知识准确性和大语言模型的表达能力。检索系统确保答案基于真实的外部知识，避免了 LLM 的幻觉问题；LLM 则提供了自然流畅的语言表达能力，超越了传统问答系统的僵硬模板。

三、RAG 的核心组件

3.1 文档加载（Document Loader）

文档加载是将各种格式的文件（PDF、Word、网页、Markdown 等）转换为纯文本的过程。不同格式需要不同的解析器——PDF 需要处理页眉页脚和表格，网页需要去除 HTML 标签，Word 需要保留段落结构。这一步看似简单，但质量直接影响后续所有环节的效果。

06_rag_architecture/01_rag_overview/doc_loader.py
"""
doc_loader.py — 文档加载器实现
支持多种文档格式的加载和文本提取。
"""
from pathlib import Path
from typing import Optional


class DocumentLoader:
    """
    文档加载器：将各种格式的文件转换为纯文本。

    支持的格式：
    - .txt: 直接读取
    - .md: 去除 Markdown 标记
    - .html: 去除 HTML 标签
    """

    @staticmethod
    def load_txt(filepath: str) -> str:
        """加载纯文本文件"""
        path = Path(filepath)
        return path.read_text(encoding="utf-8")

    @staticmethod
    def load_markdown(filepath: str) -> str:
        """加载 Markdown 文件，去除格式标记"""
        text = Path(filepath).read_text(encoding="utf-8")
        # 去除标题标记
        text = text.replace("# ", "").replace("## ", "")
        # 去除粗体和斜体标记
        text = text.replace("**", "").replace("*", "")
        return text.strip()

    @staticmethod
    def load_html(filepath: str) -> str:
        """加载 HTML 文件，提取纯文本"""
        import re
        html = Path(filepath).read_text(encoding="utf-8")
        # 去除所有 HTML 标签
        text = re.sub(r"<[^>]+>", " ", html)
        # 清理多余空白
        text = " ".join(text.split())
        return text

    @classmethod
    def load(cls, filepath: str) -> Optional[str]:
        """根据文件扩展名自动选择加载方式"""
        ext = Path(filepath).suffix.lower()
        loaders = {
            ".txt": cls.load_txt,
            ".md": cls.load_markdown,
            ".html": cls.load_html,
        }
        loader = loaders.get(ext)
        if loader is None:
            print(f"不支持的文件格式: {ext}")
            return None
        return loader(filepath)

3.2 文本分块（Text Chunking）

长文档不能直接作为一个整体进行 Embedding 和检索——一方面超出模型的上下文窗口限制，另一方面大文本块的 Embedding 会丢失细粒度语义。分块的目的是将长文档切分为固定大小（通常 200-1000 字符）的文本块，每个块独立 Embedding 和检索。

分块策略很关键：按固定字符数切分简单但可能切断语义完整性；按段落切分保留语义但块大小不均匀；滑动窗口重叠（相邻块之间保留部分重叠）可以避免上下文断裂。实际项目中通常组合使用多种策略。

3.3 Embedding 编码

将每个文本块转换为高维向量（768-1024 维），使其能够在向量空间中进行语义相似度比较。这一步依赖模块五学到的 Embedding 模型（BGE-M3、OpenAI 等）。

3.4 向量存储与检索

将所有文本块的向量存储到向量数据库（Milvus、Qdrant 等）中。当用户发起查询时，将查询文本也编码为向量，然后在数据库中搜索最相似的 K 个文本块。

06_rag_architecture/01_rag_overview/vector_store.py
"""
vector_store.py — 简易向量存储实现
使用 FAISS 或内存存储向量，支持相似度检索。
"""
import math
from typing import Optional


class MemoryVectorStore:
    """
    内存向量存储：将向量和文本存储在内存中，
    通过余弦相似度进行检索。

    适用于小规模数据的教学演示。
    """

    def __init__(self) -> None:
        self._vectors: list[list[float]] = []
        self._texts: list[str] = []
        self._metadata: list[dict] = []

    def add(self, vector: list[float], text: str, metadata: Optional[dict] = None) -> None:
        """
        添加一个向量到存储中。

        参数：
        - vector (list[float]): 嵌入向量
        - text (str): 对应的文本
        - metadata (dict): 元数据（可选）
        """
        self._vectors.append(vector)
        self._texts.append(text)
        self._metadata.append(metadata or {})

    def _cosine_similarity(self, vec1: list[float], vec2: list[float]) -> float:
        """计算余弦相似度"""
        dot = sum(a * b for a, b in zip(vec1, vec2))
        norm1 = math.sqrt(sum(a * a for a in vec1))
        norm2 = math.sqrt(sum(b * b for b in vec2))
        if norm1 == 0 or norm2 == 0:
            return 0.0
        return dot / (norm1 * norm2)

    def search(self, query_vector: list[float], top_k: int = 3) -> list[dict]:
        """
        检索最相似的 K 个向量。

        参数：
        - query_vector (list[float]): 查询向量
        - top_k (int): 返回结果数

        返回：
        - list[dict]: 包含文本、相似度和元数据的结果列表
        """
        scores = []
        for i, vec in enumerate(self._vectors):
            sim = self._cosine_similarity(query_vector, vec)
            scores.append({
                "text": self._texts[i],
                "similarity": sim,
                "metadata": self._metadata[i],
            })
        # 按相似度降序排序
        scores.sort(key=lambda x: x["similarity"], reverse=True)
        return scores[:top_k]

3.5 Prompt 构建

将检索到的相关文本块与用户查询组合成一个完整的 Prompt，提供给大语言模型。Prompt 的质量直接影响回答的准确性——需要清晰地区分"参考资料"和"用户问题"，并明确告诉模型如何基于参考资料回答。

3.6 LLM 生成

大语言模型根据构建好的 Prompt 生成回答。模型会先理解参考资料的内容，然后结合用户问题，生成基于参考资料的准确回答。

06_rag_architecture/01_rag_overview/rag_pipeline.py
"""
rag_pipeline.py — RAG 检索增强生成管道实现
包含文档加载、分块、Embedding、检索、Prompt 构建的完整流程。
"""
import os
from typing import Optional
from dataclasses import dataclass, field


@dataclass
class Document:
    """文档对象：包含文本内容和元数据"""
    text: str
    metadata: dict = field(default_factory=dict)
    doc_id: str = ""


class DocumentChunker:
    """
    文档分块器：将长文档切分为固定大小的文本块。

    分块策略：
    1. 按固定字符数分割（控制块大小）
    2. 滑动窗口重叠（避免上下文断裂）
    """

    def __init__(self, chunk_size: int = 500, overlap: int = 50):
        self.chunk_size = chunk_size
        self.overlap = overlap

    def chunk_document(self, doc: Document) -> list[Document]:
        """
        将长文档切分为多个文本块。

        使用滑动窗口策略：
        - 每块最大 chunk_size 字符
        - 相邻块之间重叠 overlap 字符
        - 避免语义被硬切断
        """
        text = doc.text
        chunks = []
        start = 0

        while start < len(text):
            end = start + self.chunk_size
            chunk_text = text[start:end]
            chunk_id = f"{doc.doc_id}_chunk_{len(chunks)}"

            chunks.append(Document(
                text=chunk_text,
                metadata={**doc.metadata, "chunk_index": len(chunks)},
                doc_id=chunk_id,
            ))
            start = end - self.overlap  # 滑动窗口

        return chunks


class RAGPipeline:
    """
    RAG（检索增强生成）管道：整合检索和生成的完整流程。

    核心流程：
    1. 文档加载 → 2. 分块 → 3. Embedding → 4. 存储
    5. 查询 Embedding → 6. 检索 Top-K → 7. 构建 Prompt → 8. LLM 生成
    """

    def __init__(self, chunk_size: int = 500, chunk_overlap: int = 50, top_k: int = 3):
        self.chunker = DocumentChunker(chunk_size, chunk_overlap)
        self.top_k = top_k
        self._documents: list[Document] = []
        self._chunks: list[Document] = []

    def load_documents(self, texts: list[str], metadata_list: Optional[list[dict]] = None) -> None:
        """加载文档并分块"""
        for i, text in enumerate(texts):
            meta = metadata_list[i] if metadata_list else {}
            doc = Document(text=text, metadata=meta, doc_id=f"doc_{i}")
            self._documents.append(doc)
            chunks = self.chunker.chunk_document(doc)
            self._chunks.extend(chunks)

    def _build_prompt(self, query: str, context: list[Document]) -> str:
        """构建 RAG Prompt：将查询和检索到的上下文组合"""
        context_text = "\n\n".join(
            f"参考资料 {i+1}:\n{doc.text}"
            for i, doc in enumerate(context)
        )

        prompt = f"""你是一个知识助手。请根据以下参考资料回答用户的问题。

参考资料：
{context_text}

用户问题：{query}

请基于上述参考资料给出准确的回答。如果参考资料中没有相关信息，请明确告知用户。"""
        return prompt

    def query(self, question: str) -> dict:
        """执行完整的 RAG 查询流程"""
        # 1. 查询 Embedding
        query_vector = self._embed_documents([question])[0]
        # 2. 检索相关文档
        context_docs = self._search(query_vector, self.top_k)
        # 3. 构建 Prompt
        prompt = self._build_prompt(question, context_docs)

        return {
            "question": question,
            "context": [doc.text for doc in context_docs],
            "prompt": prompt,
            "num_docs_retrieved": len(context_docs),
        }

四、RAG 的核心挑战

4.1 幻觉（Hallucination）

即使提供了参考资料，大语言模型仍可能生成与参考资料不一致的内容。这种"幻觉"是 RAG 系统最需要解决的问题。缓解策略包括：在 Prompt 中明确要求基于参考资料回答、添加引用来源要求、对生成结果进行事实核查。但完全消除幻觉仍然是一个开放问题。

4.2 召回质量

RAG 的效果高度依赖检索的质量。如果检索到的文档不相关，模型会基于错误信息生成回答；如果检索漏掉了关键信息，模型会因为缺乏必要上下文而给出不完整答案。这直接依赖模块五学到的 Embedding 模型选择、索引类型、混合检索等知识。

4.3 上下文窗口限制

大语言模型的上下文窗口有限（通常 4K-128K Token）。如果检索到的文档总长度超过窗口限制，需要截断或筛选。这引入了新的决策：保留哪些文档、舍弃哪些文档？常见的策略是按检索相关性排序，优先保留最相关的文档。

4.4 知识更新延迟

虽然 RAG 允许通过更新文档库来更新知识，但文档库的更新不是实时的——需要重新加载、分块、Embedding、入库。在知识频繁变化的场景中（如实时新闻），这种更新延迟可能成为问题。解决方案包括增量更新、流式处理等。

4.5 多跳推理

当问题的答案需要跨多个文档综合推理时（多跳推理），单次检索往往不够。比如"张三开发的产品和李四的公司有什么关系？"可能需要先检索"张三开发的产品"，再检索"李四的公司"，最后综合两者的关系。这需要迭代检索（Iterative Retrieval）或递归检索（Recursive Retrieval）策略。

⚠️ RAG 常见陷阱

新手最容易犯的错误是：假设 RAG 能自动解决所有知识问题。实际上，RAG 的效果取决于文档库的质量、分块策略、检索精度、Prompt 设计等多个环节。任何一个环节出问题，最终回答的质量都会下降。建议从简单的场景开始，逐步优化每个环节。

六、小结

RAG（检索增强生成）将外部知识检索与大语言模型生成能力相结合，解决了模型知识过期和幻觉两大核心问题。RAG 的工作流程分为两个阶段：索引阶段（文档加载 → 分块 → Embedding → 存储）和检索增强生成阶段（查询 → 检索 → Prompt 构建 → LLM 生成）。核心组件包括文档加载器、分块器、Embedding 模型、向量数据库和 LLM。

RAG 面临的核心挑战包括幻觉、召回质量、上下文窗口限制、知识更新延迟和多跳推理。解决这些挑战需要在各个环节持续优化——从文档处理质量、分块策略、检索算法到 Prompt 设计。在后续的章节中，我们将逐一深入每个环节，学习具体的优化策略和实践方法。
