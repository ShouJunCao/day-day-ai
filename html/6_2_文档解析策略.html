6.2 文档解析策略

模块六：RAG 系统构建 预计学习：45 分钟

学习目标

  • 理解 RAG 系统中多格式文档解析的必要性
  • 掌握 Markdown、HTML、TXT 等常见格式的解析策略
  • 学会使用正则表达式进行文本清洗和格式化
  • 能够构建统一的文档解析器架构

一、为什么需要文档解析？

在实际的 RAG 应用场景中，知识库通常包含多种格式的文档：技术文档可能是 Markdown 格式，网页内容需要解析 HTML，用户手册可能是 PDF 或 Word 文档，日志文件则是纯文本。每种格式都有其特殊的标记语法和结构特征。

文档解析的核心目标是从各种格式中提取纯净的文本内容，同时保留必要的语义信息。这个过程需要处理：格式标记（如 Markdown 的 #、*）、标签（如 HTML 的

、

）、特殊字符（如 HTML 实体 &lt;）等。

如果没有良好的文档解析，后续的分块和 Embedding 都会受到影响。例如，Markdown 中的链接如果处理不当，可能会把 URL 也当作正文内容；HTML 中的脚本和样式代码如果被保留，会严重干扰语义理解。因此，文档解析是 RAG 系统中质量控制的第一个关卡。

此外，不同格式的文档在信息密度上也存在差异。Markdown 通常比较简洁，而 HTML 可能包含大量导航、广告等无关内容。一个优秀的解析器需要能够识别并过滤这些噪声，只保留对用户有价值的信息。

二、Markdown 文档解析

Markdown 是一种轻量级标记语言，广泛用于技术文档、博客文章和 README 文件。解析 Markdown 的核心是去除格式标记，保留文本内容。

Markdown 的设计初衷是让写作者专注于内容而非格式，因此它的标记相对简单直观。但在解析时，我们需要处理多种标记类型：标题使用 # 号，粗体和斜体使用 * 号，链接使用方括号和圆括号，代码块使用三个反引号。每种标记的处理逻辑都不同，需要仔细设计。

2.1 常见的 Markdown 标记

标记类型 语法示例 处理方式
标题 # 一级标题 去除 # 号，保留文本
粗体/斜体 **粗体** *斜体* 去除 * 号
链接 [文字](URL) 提取文字部分
图片 ![alt](URL) 完全删除
代码块 ```code``` 删除整个代码块
引用 > 引用内容 去除 > 号

2.2 Markdown 解析器实现

06_rag_architecture/02_doc_parsing/doc_parser.py
class MarkdownParser:
    """
    Markdown 文档解析器。

    原理：使用正则表达式去除 Markdown 标记，
    保留文本内容并清理格式符号。
    """

    @staticmethod
    def parse(filepath: str) -> ParsedDocument:
        """解析 Markdown 文件"""
        path = Path(filepath)
        text = path.read_text(encoding="utf-8")

        # 去除代码块标记（保留代码内容）
        text = re.sub(r"```[\s\S]*?```", "", text)
        # 去除图片标记
        text = re.sub(r"!\[.*?\]\(.*?\)", "", text)
        # 将链接替换为纯文本
        text = re.sub(r"\[(.*?)\]\(.*?\)", r"\1", text)
        # 去除标题标记
        text = re.sub(r"^#{1,6}\s+", "", text, flags=re.MULTILINE)
        # 去除粗体/斜体标记
        text = text.replace("**", "").replace("*", "")
        text = text.replace("__", "").replace("_", "")
        # 去除引用标记
        text = re.sub(r"^>\s+", "", text, flags=re.MULTILINE)

        return ParsedDocument(
            text=text.strip(),
            source=str(path),
            format="md",
            metadata={"original_length": len(path.read_text(encoding="utf-8"))},
        )
💡 解析顺序很重要

Markdown 解析时需要按照特定顺序处理标记：先处理代码块（避免内部标记被误处理），再处理图片，最后处理链接和文本格式。错误的顺序可能导致内容丢失或格式混乱。

三、HTML 文档解析

HTML 解析比 Markdown 更复杂，因为 HTML 包含大量标签、脚本、样式等元素。我们的目标是提取正文内容，去除所有标记和非内容元素。

HTML 文档的结构层次通常很深：最外层是 html 标签，包含 head 和 body 两部分。head 中包含元数据、脚本和样式定义，body 中才是真正的页面内容。但 body 内部也可能包含导航栏、侧边栏、页脚等非核心内容，需要通过合理的解析策略来过滤。

另一个挑战是 HTML 实体编码。浏览器为了正确显示特殊字符（如 <、>、&），会将它们转换为 HTML 实体（如 <、>、&）。解析时需要将这些实体还原为原始字符，否则会影响后续的自然语言处理。

3.1 HTML 解析器实现

class HTMLParser:
    """
    HTML 文档解析器。

    原理：使用正则表达式去除 HTML 标签和脚本，
    提取正文内容并清理空白字符。
    """

    @staticmethod
    def parse(filepath: str) -> ParsedDocument:
        """解析 HTML 文件"""
        path = Path(filepath)
        html = path.read_text(encoding="utf-8")

        # 去除 ", "", html, flags=re.IGNORECASE)
        text = re.sub(r"", "", text, flags=re.IGNORECASE)
        # 去除所有 HTML 标签
        text = re.sub(r"<[^>]+>", " ", text)
        # 解码 HTML 实体
        text = text.replace("&", "&")
        text = text.replace("<", "<")
        text = text.replace(">", ">")
        text = text.replace(" ", " ")
        # 清理多余空白
        text = re.sub(r"\s+", " ", text).strip()

        return ParsedDocument(
            text=text,
            source=str(path),
            format="html",
            metadata={"original_length": len(html)},
        )

3.2 关键正则表达式解析

正则表达式 作用 示例
<script[\s\S]*?</script> 匹配 script 标签及内容 删除 JavaScript 代码
<[^>]+> 匹配所有 HTML 标签 删除 <p>, <div> 等
\s+ 匹配连续空白字符 合并多个空格为一个
⚠️ 正则表达式的局限性

使用正则表达式解析 HTML 虽然简单快速，但无法处理嵌套标签、不规范的 HTML 结构等复杂情况。对于生产环境，建议使用专业的 HTML 解析库（如 BeautifulSoup 或 lxml）。

四、统一文档解析器架构

在实际应用中，我们需要处理多种格式的文档。设计一个统一的文档解析器架构可以简化代码，提高可维护性。

统一解析器的核心思想是使用策略模式：定义一个通用的解析接口，为每种文件格式实现专门的解析器，然后通过注册表将文件扩展名映射到对应的解析器。这样当需要支持新格式时，只需要添加新的解析器类，而不需要修改主流程代码。

这种架构还有利于异常隔离。当某个文件解析失败时，不会影响其他文件的处理。同时，统一的输出格式（ParsedDocument）让下游的分块和 Embedding 模块无需关心文档的原始格式，降低了系统复杂度。

4.1 核心代码实现

class DocumentParser:
    """
    统一文档解析器：根据文件扩展名自动选择解析方式。

    支持的格式：
    - .txt: 直接读取
    - .md: Markdown 标记去除
    - .html: HTML 标签去除
    """

    # 解析器注册表
    PARSERS = {
        ".txt": TXTParser.parse,
        ".md": MarkdownParser.parse,
        ".html": HTMLParser.parse,
    }

    @classmethod
    def parse(cls, filepath: str) -> Optional[ParsedDocument]:
        """根据文件扩展名自动选择解析方式"""
        ext = Path(filepath).suffix.lower()
        parser = cls.PARSERS.get(ext)

        if parser is None:
            print(f"[警告] 不支持的文件格式: {ext}")
            return None

        try:
            result = parser(filepath)
            print(f"[成功] {filepath} → {result.char_count} 字符")
            return result
        except Exception as e:
            print(f"[错误] 解析失败: {filepath} - {e}")
            return None

4.2 设计优势

设计特性 实现方式 优势
策略模式 PARSERS 字典注册 易于扩展新格式
统一接口 所有解析器返回 ParsedDocument 下游处理逻辑统一
异常隔离 try-except 包裹 单个文件失败不影响整体
批量处理 parse_batch() 方法 支持大规模文档处理

五、PDF 和 Word 文档解析

PDF 和 Word 是办公场景中常见的文档格式，它们的解析比纯文本格式复杂得多，需要专门的库来处理。

PDF（Portable Document Format）是一种固定布局的文档格式，设计初衷是为了保证文档在不同设备上的显示一致性。这种特性使得 PDF 的文本提取变得困难：文本可能分散在不同的坐标位置，表格没有明确的结构标记，甚至可能存在扫描版 PDF（图片而非文本）。因此，PDF 解析通常需要依赖专业的第三方库。

Word 文档（.docx 格式）实际上是一个 ZIP 压缩包，内部包含 XML 文件来描述文档结构和内容。这种基于 XML 的设计使得 Word 文档的解析相对简单，可以准确提取段落、表格、样式等信息。但需要注意的是，旧版 .doc 格式与 .docx 完全不同，需要不同的处理方式。

5.1 PDF 解析示例

# PDF 解析示例（需要安装 PyPDF2）
def parse_pdf(filepath: str) -> str:
    """使用 PyPDF2 提取 PDF 文本"""
    from PyPDF2 import PdfReader
    
    reader = PdfReader(filepath)
    text = ""
    for page in reader.pages:
        text += page.extract_text()
    return text.strip()

# 高级解析：使用 pdfplumber 提取表格
def parse_pdf_with_tables(filepath: str) -> dict:
    """使用 pdfplumber 提取文本和表格"""
    import pdfplumber
    
    result = {"text": "", "tables": []}
    with pdfplumber.open(filepath) as pdf:
        for page in pdf.pages:
            result["text"] += page.extract_text()
            tables = page.extract_tables()
            result["tables"].extend(tables)
    return result

5.2 Word 解析示例

# Word 解析示例（需要安装 python-docx）
def parse_docx(filepath: str) -> str:
    """使用 python-docx 提取 Word 文档文本"""
    from docx import Document
    
    doc = Document(filepath)
    paragraphs = [para.text for para in doc.paragraphs]
    return "\n".join(paragraphs).strip()

# 高级解析：提取表格内容
def parse_docx_with_tables(filepath: str) -> dict:
    """提取 Word 文档的文本和表格"""
    from docx import Document
    
    doc = Document(filepath)
    result = {"paragraphs": [], "tables": []}
    
    # 提取段落
    for para in doc.paragraphs:
        if para.text.strip():
            result["paragraphs"].append(para.text)
    
    # 提取表格
    for table in doc.tables:
        table_data = []
        for row in table.rows:
            row_data = [cell.text for cell in row.cells]
            table_data.append(row_data)
        result["tables"].append(table_data)
    
    return result
📚 依赖安装

PDF 和 Word 解析需要安装第三方库：pip install PyPDF2 pdfplumber python-docx。对于扫描版 PDF，还需要安装 OCR 工具（如 Tesseract）。

六、常见问题与最佳实践

6.1 文档解析常见问题

问题 原因 解决方案
中文乱码 文件编码不匹配 使用 UTF-8 编码读取，失败时尝试 GBK
HTML 实体未解码 遗漏实体替换 使用 html.unescape() 或手动替换
Markdown 链接丢失 正则匹配顺序错误 先提取链接文字，再删除标记
PDF 表格提取失败 PyPDF2 不支持表格 使用 pdfplumber 或 camelot

6.2 最佳实践清单

  • 统一输出格式：所有解析器返回相同的 ParsedDocument 结构
  • 保留元数据：记录原始文件路径、格式、长度等信息
  • 异常处理：使用 try-except 捕获解析错误，避免程序崩溃
  • 批量处理：提供 parse_batch() 方法支持大规模文档
  • 渐进式增强：先支持简单格式（TXT/MD），再添加复杂格式（PDF/Word）
  • 日志记录：记录解析成功/失败的文件数量和原因

七、小结

文档解析是 RAG 系统的第一个关键环节，直接影响后续的分块、Embedding 和检索质量。本章我们学习了：

  • Markdown 解析：使用正则表达式去除格式标记，保留文本内容
  • HTML 解析：分步骤去除脚本、样式、标签，解码实体
  • 统一架构：使用策略模式和解析器注册表，支持多格式扩展
  • PDF/Word 解析：使用专业库（PyPDF2、python-docx）处理复杂格式
  • 最佳实践：统一输出格式、异常处理、批量处理、日志记录

在实际项目中，建议先实现简单格式（TXT、Markdown、HTML），验证整体流程后再添加复杂格式（PDF、Word）的支持。这种渐进式开发方式可以降低风险，快速交付可用的 MVP 版本。

💡 下一步建议

完成文档解析后，下一步是分块策略（6.3 节）。分块质量直接影响 Embedding 的效果和检索的准确性。建议先使用固定长度分块（如 500 字符），然后根据实际效果调整分块大小和重叠策略。
