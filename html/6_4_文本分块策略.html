一、为什么文本分块很重要？

在 RAG 系统中，文本分块是连接文档解析和向量检索的关键桥梁。分块质量直接影响 Embedding 的效果和检索的准确性。如果分块过大，Embedding 会丢失细粒度语义；如果分块过小，检索结果可能缺乏足够的上下文。

分块的核心挑战在于：如何在保持语义完整性的同时，控制块的大小以适应 Embedding 模型的限制。不同的文档类型和内容结构需要不同的分块策略。例如，技术文档适合按章节分块，而新闻文章适合按段落分块。

此外，分块策略还会影响检索的粒度。细粒度分块（小块）能精确定位相关信息，但可能缺乏上下文；粗粒度分块（大块）提供完整上下文，但可能引入噪声。因此，选择合适的分块策略需要权衡检索精度和上下文完整性。

在实际项目中，分块往往是 RAG 系统调优的第一步。一个合适的分块策略可以显著提升检索准确率，而错误的分块策略会导致后续所有优化都难以见效。因此，在构建 RAG 系统时，应该投入足够的时间来评估和选择分块策略。

二、固定长度分块

固定长度分块是最简单直接的分块策略。它按固定字符数将文本切分为多个块，相邻块之间可以设置重叠部分以避免语义被硬切断。

这种策略的优势在于实现简单、速度极快，不需要任何自然语言处理知识。但它的缺点也很明显：完全不考虑语义边界，可能会在句子中间切断文本，导致每个块的语义不完整。对于信息密度均匀的文本（如日志文件），这种策略效果不错；但对于结构化文档（如论文、报告），效果往往不理想。

2.1 原理与实现

固定长度分块使用滑动窗口策略：从文本开头开始，每次截取 chunk_size 个字符作为一个块，然后向后移动 chunk_size - overlap 个字符继续截取。这种策略实现简单、速度快，但完全不考虑语义边界，可能会在句子中间切断文本。

class FixedSizeChunker:
    """
    固定长度分块器：按固定字符数切分文本。

    特点：
    - 实现简单，速度快
    - 不考虑语义边界
    - 适合均匀分布的文本
    """

    def __init__(self, chunk_size: int = 500, overlap: int = 50):
        self.chunk_size = chunk_size
        self.overlap = overlap

    def chunk(self, text: str) -> List[Chunk]:
        """将文本切分为固定大小的块"""
        chunks = []
        start = 0

        while start < len(text):
            end = start + self.chunk_size
            chunk_text = text[start:end]

            chunks.append(Chunk(
                text=chunk_text,
                index=len(chunks),
                metadata={"strategy": "fixed_size"},
            ))
            start = end - self.overlap  # 滑动窗口

        return chunks

三、语义分块

语义分块在句子边界处切分文本，避免在句子中间切断。它首先将文本按句子分割，然后累积句子直到达到目标大小，在句子边界处切分。

语义分块的关键在于识别句子边界。中文的句子通常以句号、问号、叹号等标点符号结束。通过正则表达式匹配这些标点符号，可以将文本分割为句子列表，然后在句子边界处进行切分。

这种方法的优势是保持了句子的完整性，不会在句子中间切断语义。缺点是块大小不均匀，有些块可能远小于目标大小，有些可能略大于目标大小。对于 Embedding 模型来说，块大小不均匀可能导致向量质量波动，但通常比固定长度分块的语义完整性更好。

在实际应用中，语义分块适合处理文章、博客、新闻等自然语言文本。这些文本通常有清晰的句子结构，按句子切分能够保持语义的连贯性。但对于代码文档或技术手册，语义分块可能不如递归分块有效。

class SemanticChunker:
    """
    语义分块器：基于语义相似度动态调整块边界。

    原理：
    1. 按句子分割文本
    2. 累积句子直到达到目标大小
    3. 在句子边界切分（不切断句子）
    """

    def __init__(self, chunk_size: int = 500, overlap: int = 50):
        self.chunk_size = chunk_size
        self.overlap = overlap
        # 句子分割正则
        self.sentence_pattern = re.compile(r'(?<=[。！？；.!?\n])\s*')

    def chunk(self, text: str) -> List[Chunk]:
        """基于语义边界切分文本"""
        sentences = self._split_sentences(text)
        chunks = []
        current_chunk = []
        current_length = 0

        for sentence in sentences:
            if current_length + len(sentence) > self.chunk_size and current_chunk:
                chunks.append(Chunk(text=" ".join(current_chunk), ...))
                current_chunk = self._get_overlap()

            current_chunk.append(sentence)
            current_length += len(sentence)

        return chunks

四、递归分块

递归分块按层次结构逐步细化切分文本。它首先尝试在大边界（如段落）处切分，如果块仍然过大，再逐步使用更小的边界（如句子、分号、空格）进行切分。

递归分块是 LangChain 等主流框架默认推荐的分块策略。它的核心优势是既考虑了文档的自然结构，又能在结构不明显时退回到更细粒度的切分。这种"先大后小"的策略能够最大程度地保持语义完整性，同时确保块大小在可控范围内。

五、Sentence Window 分块

Sentence Window 分块以单个句子为核心，保留前后若干句作为上下文窗口。检索时使用核心句子进行匹配，生成时使用完整上下文提供背景信息。

5.1 核心思想

Sentence Window 的核心思想是检索与生成分离：检索阶段使用核心句子（精确匹配），生成阶段使用完整上下文（提供背景）。这种设计既能保证检索精度，又能保证生成的连贯性。

5.2 适用场景

场景为什么适合示例
法律文档需要精确匹配条款，同时需要上下文合同条款检索
医学文献医学术语需要精确匹配，但理解需要上下文症状 - 疾病匹配
技术文档API 文档需要精确匹配函数名代码示例检索

5.3 代码实现

class SentenceWindowChunker:
    """
    Sentence Window 分块器：以句子为中心，保留上下文窗口。

    特点：
    - 每个块以单个句子为核心
    - 包含前后若干句作为上下文
    - 检索时使用核心句子，生成时使用完整上下文
    """

    def __init__(self, window_size: int = 3):
        self.window_size = window_size
        self.sentence_pattern = re.compile(r'(?<=[。！？.!?])\s*')

    def chunk(self, text: str) -> List[Chunk]:
        """生成带上下文窗口的句子块"""
        sentences = self._split_sentences(text)
        chunks = []

        for i, sentence in enumerate(sentences):
            # 获取前后上下文
            start = max(0, i - self.window_size)
            end = min(len(sentences), i + self.window_size + 1)
            context = " ".join(sentences[start:end])

            chunks.append(Chunk(
                text=context,
                index=i,
                metadata={
                    "core_sentence": sentence,
                    "core_index": i,
                    "context_start": start,
                    "context_end": end,
                },
            ))

        return chunks

七、分块策略选择建议

选择合适的分块策略需要考虑文档类型、Embedding 模型限制和检索需求。以下是实用的选择建议：

  • 日志/对话记录：固定长度分块，按行或按轮次切分
  • 文章/博客：语义分块，保持段落完整性
  • 技术文档/论文：递归分块，利用章节结构
  • 法律/医学文档：Sentence Window，精确匹配 + 上下文
💡 实用建议

建议先用递归分块做基线测试，然后根据实际效果调整。如果块大小差异过大，可以切换到语义分块；如果需要更精确的检索，可以尝试 Sentence Window。分块策略的选择应该基于实际的检索效果评估，而不是理论分析。

八、小结

本章介绍了四种主流文本分块策略：固定长度分块实现简单但不考虑语义边界；语义分块在句子边界处切分，保持语义完整性；递归分块按层次结构逐步细化，兼顾效率和语义；Sentence Window 以核心句子为中心保留上下文窗口，适合精确检索场景。

分块质量直接影响 Embedding 的效果和检索的准确性。在实际项目中，建议先用递归分块做基线测试，然后根据文档类型和检索需求调整策略。同时，建议建立分块效果评估机制，定期检查分块质量，确保 RAG 系统的整体效果。
