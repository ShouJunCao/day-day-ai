模块六：RAG 系统构建 预计学习：50 分钟

学习目标

  • 理解检索优化在 RAG 系统中的重要性
  • 掌握四种主流检索优化策略的原理和实现
  • 学会根据场景选择合适的优化策略

一、为什么需要检索优化？

在 RAG 系统中，检索质量直接决定了回答质量。然而，用户的原始查询往往不够精确，可能缺少关键信息、使用不准确的术语，或者表达方式与文档不匹配。这些问题会导致检索结果不理想，进而影响最终的回答质量。

检索优化的核心目标是弥补用户查询和文档库之间的表达差距。通过改写查询、生成假设性文档、多角度检索等技术手段，可以显著提升检索的召回率和准确率。

研究表明，简单的查询改写可以将 RAG 系统的检索准确率提升 15-30%。这对于实际应用来说是非常可观的改进。而且，这些优化技术通常不需要修改底层的数据和模型，只需要在查询阶段增加处理逻辑即可。

此外，检索优化还能改善用户体验。用户不需要学习专业的查询语法或术语，只需用自然语言表达问题，系统就能自动优化查询并返回准确的结果。这种"傻瓜式"的交互方式大大降低了 RAG 系统的使用门槛。

二、Query 改写（Query Rewriting）

Query 改写是最直接有效的检索优化策略。它使用大语言模型将用户的原始查询改写为更精确、更专业的检索查询，从而提高检索效果。

这种策略特别适合处理口语化和模糊的查询。用户在日常交流中往往使用简略的表达方式，而文档库中通常使用正式的、结构化的语言。Query 改写通过 LLM 的语义理解能力，在两者之间架起桥梁，使检索更加精准。

2.1 核心原理

Query 改写的核心思想是：用户通常不会使用最专业的术语来表达查询，而文档库中可能使用更专业的术语。通过 LLM 的语义理解能力，可以将用户的自然语言查询转换为更适合检索的形式。

改写过程包括以下几个关键步骤：

  1. 意图识别：理解用户查询的真实意图
  2. 术语标准化：将口语化表达转换为专业术语
  3. 同义词扩展：添加相关的同义词和近义词
  4. 查询结构化：将复杂查询拆分为多个子查询

三、HyDE（假设性文档嵌入）

HyDE（Hypothetical Document Embeddings）是一种巧妙的检索优化技术。它不是直接检索用户查询，而是先让 LLM 生成一个假设性回答文档，然后用这个假设性文档去检索真实文档。

3.1 为什么 HyDE 有效？

HyDE 有效的核心原因是缩小了查询和文档之间的表示差距。用户查询通常很短（几个词到一句话），而文档内容丰富（几百到几千字）。两者的 Embedding 向量在空间中的距离较远，直接检索效果不佳。

HyDE 通过让 LLM 生成一个假设性文档，将这个短查询扩展为一个与真实文档格式和长度相近的文本。这个假设性文档虽然不是正确答案，但它在向量空间中更接近真实的文档，从而提高了检索效果。

3.2 代码实现

class HyDERetriever:
    """
    HyDE 检索器：假设性文档嵌入检索。

    原理：
    1. 让 LLM 根据查询生成一个假设性回答文档
    2. 将假设性文档编码为向量
    3. 用假设性文档的向量去检索真实文档
    4. 真实文档与假设性文档在向量空间中更接近
    """

    def __init__(self, embedding_fn, generation_fn=None):
        self.embedding_fn = embedding_fn
        self.generation_fn = generation_fn
        self.hyde_prompt = """请根据以下问题生成一个详细的回答：

问题：{query}

回答："""

    def retrieve(self, query: str, top_k: int = 5) -> list:
        """执行 HyDE 检索"""
        # 步骤 1：生成假设性文档
        hypothetical_doc = self.generation_fn(
            self.hyde_prompt.format(query=query)
        )
        # 步骤 2：编码假设性文档
        query_vector = self.embedding_fn(hypothetical_doc)
        # 步骤 3：检索真实文档
        return self._vector_search(query_vector, top_k)

四、Multi-Query（多角度查询）

Multi-Query 策略的核心思想是：让 LLM 从不同角度为同一个问题生成多个查询，分别检索，然后合并结果。这样可以覆盖更多的相关信息，减少单一查询的偏差。

class MultiQueryRetriever:
    """
    Multi-Query 检索器：多角度查询检索。

    原理：
    1. 让 LLM 从不同角度生成多个相关查询
    2. 分别用每个查询进行检索
    3. 合并所有检索结果，去重排序
    4. 返回最终的综合结果
    """

    def __init__(self, num_queries: int = 3):
        self.num_queries = num_queries

    def retrieve(self, query: str, search_fn) -> list:
        """执行 Multi-Query 检索"""
        # 步骤 1：生成多个查询
        queries = self._generate_queries(query)

        # 步骤 2：分别检索
        all_results = []
        for q in queries:
            results = search_fn(q)
            all_results.extend(results)

        # 步骤 3：去重合并
        return self._deduplicate(all_results)

五、Step-back（后退一步）

Step-back 检索是一种独特的优化策略。它不是直接检索用户的具体问题，而是先生成一个更抽象、更高层次的问题，用这个高层次问题检索一般性原理，再用原始问题检索具体实例，最后将两者结合。

5.1 核心思想

Step-back 的核心思想是先理解原理，再看实例。这对于需要背景知识的复杂问题特别有效。例如，用户问"Transformer 中的注意力机制如何实现？"，直接检索可能只找到代码片段，而先检索"什么是注意力机制"能找到原理文档，再结合代码检索就能提供更全面的回答。

5.2 代码实现

class StepBackRetriever:
    """
    Step-back 检索器：后退一步检索。

    原理：
    1. 生成一个更抽象、更高层次的问题
    2. 用高层次问题检索一般性原理文档
    3. 用原始问题检索具体实例文档
    4. 合并两种检索结果，提供全面回答
    """

    def __init__(self):
        self.step_back_prompt = """请生成一个更高层次、更抽象的问题，
涵盖以下具体问题的核心概念。

具体问题：{query}

高层次问题："""

    def retrieve(self, query: str, search_fn) -> dict:
        """执行 Step-back 检索"""
        # 步骤 1：生成 step-back 问题
        step_back_query = self._generate_step_back(query)

        # 步骤 2：分别检索
        principle_results = search_fn(step_back_query)  # 原理
        specific_results = search_fn(query)              # 实例

        return {
            "original_query": query,
            "step_back_query": step_back_query,
            "principle_results": principle_results,
            "specific_results": specific_results,
        }

Step-back 的核心思想是先理解原理再看实例。这对于需要背景知识的复杂问题特别有效。例如，用户问"Transformer 中的注意力机制如何实现？"，直接检索可能只找到代码片段，而先检索"什么是注意力机制"能找到原理文档，再结合代码检索就能提供更全面的回答。

七、组合策略

在实际应用中，这些策略并不是互斥的。可以根据需要组合使用，获得更好的效果。例如：

  • Query 改写 + HyDE：先改写查询使其更精确，再用 HyDE 生成假设文档检索
  • Step-back + Multi-Query：在原理和实例两个层面都进行多角度检索
  • Query 改写 + Multi-Query：先改写原始查询，再从多个角度生成相关查询
⚠️ 性能开销警告

每种优化策略都会增加 LLM 调用次数和检索次数，从而影响响应时间和成本。Multi-Query 需要 3-5 次检索，Step-back 需要 2 次检索。在生产环境中，需要根据延迟要求和预算合理选择策略。建议先评估单策略效果，再考虑组合使用。

八、小结

本章介绍了四种主流的检索优化策略：Query 改写通过优化查询表达来提升检索效果；HyDE 通过生成假设性文档缩小查询与文档的表示差距；Multi-Query 通过多角度查询覆盖更多信息；Step-back 通过先理解原理再看实例的方式提供更全面的回答。

这些策略各有优劣，适用场景不同。Query 改写适合模糊查询，HyDE 适合开放域问答，Multi-Query 适合复杂问题，Step-back 适合需要背景知识的问题。在实际项目中，建议先用 Query 改写做基线测试，根据效果逐步添加其他策略，并监控性能和成本的平衡。

值得注意的是，这些策略的性能开销各不相同。Query 改写只需一次 LLM 调用和一次检索，开销最小；Multi-Query 需要多次检索，开销最大。在生产环境中，需要根据延迟要求和预算合理选择策略，或者在低峰时段使用更复杂的策略来换取更高的检索质量。
