6.6 重排序技术（BGE-Reranker、Cohere、Cross-Encoder）

模块六：RAG 系统构建 预计学习：50 分钟

学习目标

  • 理解重排序在 RAG 系统中的作用和价值
  • 掌握 Cross-Encoder、BGE-Reranker、Cohere Rerank 三种重排序策略
  • 学会两阶段检索（粗排 + 精排）的完整流程
  • 能够根据场景选择合适的重排序方案

一、为什么需要重排序？

在 RAG 系统中，向量检索（使用余弦相似度）是第一步筛选，它基于 Embedding 向量的距离来评估文档相关性。然而，向量检索有一个明显的局限：查询和文档是独立编码的，两者之间没有深度交互。

这意味着向量检索只能捕捉到大致相关的文档，但无法精确判断哪个文档最相关。特别是在候选文档之间差异细微时，向量排序的结果往往不够准确。比如两个文档都包含"Transformer"关键词，但一个详细讲解了注意力机制原理，另一个只是简单提及，向量检索可能无法区分两者的相关性差异。

重排序技术通过在初筛结果上增加一层深度相关性计算，让查询和文档进行充分交互，从而得到更精确的排序结果。研究表明，在向量检索后增加重排序步骤，可以将检索准确率提升 10-25%。这个提升幅度对于实际应用来说非常可观，特别是当 RAG 系统的回答质量直接取决于检索质量时。

此外，重排序还能改善用户体验。用户期望检索结果按相关性从高到低排列，而纯向量检索的结果排序往往不够精确。重排序可以确保最相关的文档排在最前面，减少用户翻找结果的时间。

二、Cross-Encoder 重排序

Cross-Encoder 是重排序最经典的方法。它将查询和文档拼接为一个输入序列，通过预训练语言模型进行编码，然后输出两者的相关性分数。

Cross-Encoder 与向量检索使用的 Bi-Encoder 有着本质的区别。Bi-Encoder 将查询和文档分别编码为独立向量，然后计算余弦相似度；而 Cross-Encoder 将两者拼接后一起编码，允许查询和文档的 token 在注意力层中充分交互。这种深度交互使得模型能够捕捉更细粒度的语义匹配信号，但也意味着每对查询 - 文档都需要一次独立的推理，速度较慢。

2.1 工作原理

与向量检索使用的 Bi-Encoder（查询和文档独立编码）不同，Cross-Encoder 允许查询和文档的 token 在注意力层中充分交互。这种深度交互使得模型能够捕捉更细粒度的语义匹配信号。

2.2 代码实现

06_rag_architecture/06_reranking/reranking.py
class CrossEncoderReranker:
    """
    Cross-Encoder 重排序器：使用 Cross-Encoder 模型对检索结果重排序。

    原理：
    1. 将查询和文档拼接为 [CLS] query [SEP] doc [SEP]
    2. 通过 Cross-Encoder 模型编码
    3. 取 [CLS] token 输出经过分类头得到相关性分数
    4. 按分数重新排序
    """

    def __init__(self, model_name: str = "cross-encoder/ms-marco-MiniLM-L-6-v2"):
        self.model_name = model_name
        self._model = None
        self._tokenizer = None

    def rerank(self, query: str, candidates: List[Tuple[str, str]], top_k: int = 10):
        """对候选文档进行重排序"""
        scored = []
        for i, (doc_id, text) in enumerate(candidates):
            score = self._compute_similarity(query, text)
            scored.append(RerankResult(
                doc_id=doc_id, text=text,
                score=score, original_rank=i + 1,
            ))
        scored.sort(key=lambda x: x.score, reverse=True)
        return scored[:top_k]

    def _compute_similarity(self, query: str, doc: str) -> float:
        """计算查询和文档的相关性分数"""
        import torch
        if self._tokenizer is None or self._model is None:
            self._load_model()
        assert self._tokenizer is not None
        assert self._model is not None

        inputs = self._tokenizer(
            query, doc, return_tensors="pt",
            truncation=True, max_length=512,
        )
        with torch.no_grad():
            outputs = self._model(**inputs)
            return outputs.logits.squeeze().item()

三、BGE-Reranker 重排序

BGE-Reranker 是智源研究院（BAAI）开发的重排序模型系列。它在 Cross-Encoder 架构基础上进行了专门优化，特别是在中文重排序任务上表现优异。

3.1 代码实现

class BGEReranker:
    """
    BGE-Reranker 重排序器：使用 BGE 系列重排序模型。

    特点：
    - 中文优化效果好
    - 支持多语言
    - 模型体积适中
    """

    def __init__(self, model_name: str = "BAAI/bge-reranker-large"):
        self.model_name = model_name
        self._model = None

    def rerank(self, query: str, candidates: List[Tuple[str, str]], top_k: int = 10):
        """对候选文档进行重排序"""
        if not candidates:
            return []

        if self._model is None:
            from FlagEmbedding import FlagReranker
            self._model = FlagReranker(self.model_name, use_fp16=True)

        pairs = [(query, text) for _, text in candidates]
        scores = self._model.compute_score(pairs, normalize=True)

        scored = []
        for i, (doc_id, text) in enumerate(candidates):
            score = scores[i] if i < len(scores) else 0.0
            scored.append(RerankResult(
                doc_id=doc_id, text=text,
                score=score, original_rank=i + 1,
            ))
        scored.sort(key=lambda x: x.score, reverse=True)
        return scored[:top_k]

四、Cohere Rerank

Cohere Rerank 是由 Cohere 公司提供的云端重排序服务。它基于 LLM 的深度语义理解能力，对文档进行精确的相关性评分。

4.1 核心优势

Cohere Rerank 最大的优势是零部署成本。用户不需要在本地安装和配置任何模型，只需要调用 API 即可获得高质量的重排序结果。这对于快速原型开发和资源有限的团队来说非常有吸引力。

此外，Cohere 的 rerank-multilingual-v3.0 模型支持多种语言，包括中文、英文、日文、韩文等。虽然其中文效果不如专门优化的 BGE-Reranker，但对于多语言混合的场景来说，它是一个方便的一站式解决方案。

七、实践建议

选择合适的重排序策略需要考虑多个因素：语言类型、数据安全要求、预算限制、延迟要求等。以下是基于实际项目经验的建议：

  • 中文项目首选 BGE-Reranker，在中文重排序任务上效果最好，且模型开源免费
  • 英文项目可使用 Cross-Encoder，ms-marco 系列模型成熟稳定，社区支持好
  • 快速原型可选 Cohere Rerank，无需本地部署，按需付费，适合验证想法
  • 初筛候选数建议 20-50，太少效果不明显，太多开销大。30 是一个不错的起点
  • 敏感数据项目避免云端方案，使用本地部署的 BGE 或 Cross-Encoder 确保数据不流出
💡 两阶段检索调优

建议先固定重排序模型，调整初筛候选数（20/30/50/100），找到准确率和延迟的最佳平衡点。通常 30-50 个候选文档是一个不错的起点。可以使用离线评估集（标注好的查询 - 文档对）来量化不同配置的效果。

八、小结

重排序是 RAG 系统中提升检索精度的关键步骤。Cross-Encoder 通过查询和文档的深度交互提供高精度排序；BGE-Reranker 在中文重排序任务上表现最优；Cohere Rerank 提供免部署的云端方案。

在实际项目中，建议采用两阶段检索策略：先用向量检索快速筛选 Top-50 候选文档，再用重排序模型精确排序 Top-5。这种组合方式兼顾了速度和精度，是生产环境下的最佳实践。中文项目首选 BGE-Reranker-large 模型，它在精度和速度之间取得了良好的平衡。

重排序的性能开销需要认真考虑。每增加一个候选文档，就需要一次额外的模型推理。对于延迟敏感的应用，建议使用 FP16 推理或模型量化来加速。对于预算有限的项目，可以先在离线环境中评估重排序的收益，确认效果提升显著后再上线。
