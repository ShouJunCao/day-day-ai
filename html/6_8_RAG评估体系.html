6.8 RAG 评估体系（RAGAS 框架）

模块六：RAG 系统构建 预计学习：50 分钟

学习目标

  • 理解 RAG 系统评估的必要性和挑战
  • 掌握 RAGAS 框架的五大核心评估指标
  • 学会构建评估数据集和执行自动化评估
  • 能够根据评估结果定位问题并优化系统

一、为什么需要 RAG 评估？

RAG 系统是一个复杂的流水线，包含文档解析、分块、Embedding、检索、重排序、上下文管理和 LLM 生成等多个环节。每个环节都可能引入质量问题，而这些问题的根源往往不容易直接定位。

传统的问答评估方法（如人工检查回答质量）效率低、成本高，且难以量化每个环节的贡献。RAGAS（RAG Assessment）框架提供了一套自动化的评估体系，能够分别评估检索和生成两个阶段的质量。

RAGAS 的核心价值在于：将 RAG 系统的评估拆解为多个独立指标，每个指标对应系统的一个环节。当某个指标得分较低时，可以直接定位到对应环节进行优化，而不是盲目地调整整个系统。

二、RAGAS 框架概览

RAGAS 框架定义了五个核心评估指标，分别覆盖检索阶段和生成阶段的质量：

这五个指标并非独立存在，而是相互关联的。例如，如果检索阶段的上下文精确度和召回率都很低，那么生成阶段的忠实度和正确性也很难达标。因此，评估时应该先关注检索阶段的指标，确保检索质量，再优化生成阶段。

指标评估对象对应环节理想值
上下文精确度 检索到的上下文是否相关 检索 + 重排序 > 0.8
上下文召回率 上下文是否覆盖真实答案信息 检索 > 0.8
答案忠实度 回答是否基于上下文（无编造） LLM 生成 > 0.9
答案相关性 回答是否直接回答问题 LLM 生成 > 0.8
答案正确性 回答与真实答案的一致程度 整体质量 > 0.8

三、上下文精确度（Context Precision）

上下文精确度评估的是：在检索到的所有文档中，有多少比例是真正相关的。这个指标反映了检索系统和重排序系统的综合效果。

计算方式：对每个检索到的文档，判断其是否包含回答所需的信息。精确度 = 相关文档数 / 总检索文档数。分数越高，说明检索结果越精确，噪声越少。

如果上下文精确度低，说明检索系统返回了太多不相关的文档。可能的原因包括：分块粒度过粗、Embedding 模型不合适、检索策略不够精确等。优化方向：改进分块策略、使用更好的 Embedding 模型、增加重排序步骤。

class ContextPrecision:
    """
    上下文精确度：评估检索到的上下文是否相关。

    原理：
    1. 对每个检索到的文档，判断其是否包含回答所需信息
    2. 计算相关文档占所有检索文档的比例
    3. 分数越高，说明检索到的上下文越精确
    """

    def compute(self, questions, contexts, ground_truths):
        """计算上下文精确度"""
        scores = []
        for q, ctx_list, gt in zip(questions, contexts, ground_truths):
            if not ctx_list:
                scores.append(0.0)
                continue

            precision_sum = 0.0
            relevant_count = 0
            for i, ctx in enumerate(ctx_list):
                is_relevant = self._is_relevant(q, ctx, gt)
                if is_relevant:
                    relevant_count += 1
                    precision_sum += relevant_count / (i + 1)

            precision = precision_sum / len(ctx_list)
            scores.append(precision)

        return sum(scores) / len(scores)

3.2 精确度与召回率的关系

四、上下文召回率（Context Recall）

上下文召回率评估的是：检索到的上下文是否覆盖了真实答案中的所有关键信息。即使检索到的文档都是相关的，如果遗漏了某些关键信息，召回率也会较低。

计算方式：从真实答案中提取关键信息（主张），检查这些信息是否能在检索到的上下文中找到。召回率 = 被覆盖的信息量 / 总信息量。

如果上下文召回率低，说明检索系统遗漏了重要信息。可能的原因包括：查询改写不足、分块策略导致信息丢失、向量检索无法覆盖某些语义等。优化方向：使用 Query 改写、Multi-Query 等检索优化技术。

4.1 代码实现

class ContextRecall:
    """
    上下文召回率：评估检索到的上下文是否覆盖了真实答案的所有信息。

    原理：
    1. 从真实答案中提取关键主张（claims）
    2. 检查每个主张是否能在检索到的上下文中找到支持
    3. 召回率 = 被支持的主张数 / 总主张数
    """

    def compute(self, contexts, ground_truths):
        """计算上下文召回率"""
        scores = []
        for ctx_list, gt in zip(contexts, ground_truths):
            if not ctx_list:
                scores.append(0.0)
                continue

            combined_ctx = " ".join(ctx_list)
            # 基于关键词覆盖度计算
            gt_words = set(gt.replace(" ", ""))
            ctx_words = set(combined_ctx.replace(" ", ""))
            recall = len(gt_words & ctx_words) / max(len(gt_words), 1)
            scores.append(min(recall, 1.0))

        return sum(scores) / len(scores)

五、答案忠实度（Faithfulness）

答案忠实度评估的是：LLM 生成的回答是否完全基于检索到的上下文，而不是凭空编造信息。这是 RAG 系统最关键的指标之一，因为"幻觉"是 LLM 最严重的问题。

计算方式：从回答中提取所有主张（claims），检查每个主张是否能在检索到的上下文中找到支持。忠实度 = 被支持的主张数 / 总主张数。

如果忠实度低，说明 LLM 在回答中编造了上下文里没有的信息。可能的原因包括：Prompt 设计不当（没有明确要求基于上下文回答）、LLM 本身的幻觉倾向、上下文信息不足以支撑完整回答等。优化方向：改进 Prompt 设计、使用更小的 Temperature、增加上下文压缩以减少噪声干扰。

class Faithfulness:
    """
    答案忠实度：评估 LLM 生成的回答是否基于检索到的上下文。

    原理：
    1. 从回答中提取主张（claims）
    2. 检查每个主张是否能在上下文中找到支持
    3. 忠实度 = 被支持的主张数 / 总主张数
    """

    def compute(self, contexts, answers):
        """计算答案忠实度"""
        scores = []
        for ctx_list, answer in zip(contexts, answers):
            if not ctx_list:
                scores.append(0.0)
                continue

            combined_ctx = " ".join(ctx_list)
            answer_words = set(answer.replace(" ", ""))
            ctx_words = set(combined_ctx.replace(" ", ""))
            faithfulness = len(answer_words & ctx_words) / max(len(answer_words), 1)
            scores.append(min(faithfulness, 1.0))

        return sum(scores) / len(scores)

六、答案相关性与正确性

6.1 答案相关性（Answer Relevancy）

答案相关性评估的是：生成的回答是否直接回答了用户的问题。一个相关性高的回答应该紧扣问题，不跑题、不冗余。

计算方法：评估回答中的关键信息与问题的相关程度。一种常用方法是让 LLM 从回答生成"反向问题"，然后检查这些反向问题是否与原问题一致。

6.2 答案正确性（Answer Correctness）

答案正确性评估的是：生成的回答与真实答案的一致程度。它综合了忠实度和相关性，是 RAG 系统的最终质量指标。

6.3 代码实现

class AnswerRelevancy:
    """答案相关性：评估回答是否直接回答了问题"""

    def compute(self, questions, answers):
        """计算答案相关性"""
        scores = []
        for q, a in zip(questions, answers):
            q_words = set(q.replace(" ", ""))
            a_words = set(a.replace(" ", ""))
            overlap = len(q_words & a_words) / max(len(q_words), 1)
            scores.append(min(overlap * 2, 1.0))
        return sum(scores) / len(scores)


class AnswerCorrectness:
    """答案正确性：评估回答与真实答案的一致程度"""

    def compute(self, answers, ground_truths):
        """计算答案正确性"""
        scores = []
        for answer, gt in zip(answers, ground_truths):
            a_words = set(answer.replace(" ", ""))
            gt_words = set(gt.replace(" ", ""))
            similarity = len(a_words & gt_words) / max(len(a_words | gt_words), 1)
            scores.append(min(similarity * 2, 1.0))
        return sum(scores) / len(scores)

七、完整 RAGAS 评估流程

RAGAS 评估器的核心是 RAGAS 类，它组合了五个独立的评估指标，对 RAG 系统进行全面的自动化评估。

7.1 评估数据准备

执行 RAGAS 评估需要准备四类数据：问题列表、每个问题对应的检索上下文、真实答案（Ground Truth）、LLM 生成的回答。这些数据可以通过离线测试集或线上日志收集获得。

7.2 代码实现

class RAGAS:
    """
    RAGAS 评估器：综合评估 RAG 系统的质量。

    核心指标：
    - context_precision: 上下文精确度
    - context_recall: 上下文召回率
    - faithfulness: 答案忠实度
    - answer_relevancy: 答案相关性
    - answer_correctness: 答案正确性
    """

    def evaluate(self, evaluation_data: RAGEvaluation) -> Dict[str, float]:
        """执行全面评估"""
        results = {}

        results["context_precision"] = self.context_precision.compute(
            evaluation_data.questions,
            evaluation_data.contexts,
            evaluation_data.ground_truths,
        )

        results["context_recall"] = self.context_recall.compute(
            evaluation_data.contexts,
            evaluation_data.ground_truths,
        )

        results["faithfulness"] = self.faithfulness.compute(
            evaluation_data.contexts,
            evaluation_data.answers,
        )

        results["answer_relevancy"] = self.answer_relevancy.compute(
            evaluation_data.questions,
            evaluation_data.answers,
        )

        results["answer_correctness"] = self.answer_correctness.compute(
            evaluation_data.answers,
            evaluation_data.ground_truths,
        )

        # 综合分数（五指标等权平均）
        results["overall_score"] = (
            results["context_precision"] * 0.2 +
            results["context_recall"] * 0.2 +
            results["faithfulness"] * 0.2 +
            results["answer_relevancy"] * 0.2 +
            results["answer_correctness"] * 0.2
        )

        return results

八、评估结果解读

建议建立自动化评估流水线，每次系统变更后自动执行评估，跟踪各指标的变化趋势。同时，定期人工抽查评估结果，确保自动化评估与人工判断一致。对于关键业务场景，建议结合人工评估和自动化评估，获得更全面的质量判断。

九、小结

RAGAS 框架为 RAG 系统提供了一套科学的评估体系。通过五个独立的指标，可以分别评估检索阶段和生成阶段的质量，快速定位问题环节。上下文精确度和召回率评估检索质量，忠实度、相关性和正确性评估生成质量。

在实际项目中，建议将 RAGAS 评估集成到 CI/CD 流程中，每次代码或配置变更后自动执行评估，确保系统质量不会因变更而下降。同时，建立评估基准线，定期对比不同配置和算法的效果，持续优化 RAG 系统的整体表现。

评估不是一次性的工作，而是一个持续迭代的过程。随着数据量的增长、用户需求的变化和模型技术的进步，评估指标和基准线也需要相应调整。建议每个季度至少执行一次全面的 RAG 评估，确保系统始终保持在最佳状态。
