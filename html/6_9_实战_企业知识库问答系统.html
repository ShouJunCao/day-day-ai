一、系统架构概览

本节我们将综合运用前面学到的所有知识，构建一个完整的企业知识库问答系统。这个系统包含了文档解析、文本分块、向量检索、重排序、上下文管理和 LLM 生成等所有核心组件。

系统分为两个阶段：导入阶段和查询阶段。导入阶段负责将原始文档解析、分块、编码并存储到向量索引中；查询阶段负责接收用户问题，检索相关文档，重排序，构建上下文，最终由 LLM 生成回答。这两个阶段共同构成了 RAG 系统的完整生命周期。

导入阶段是一次性或周期性执行的任务。当知识库中的文档有更新时，只需要重新导入新增或修改的文档，而不需要重建整个索引。查询阶段则是实时执行的，每次用户发起问题都会触发完整的检索和生成流程。

二、文档解析模块

文档解析是整个系统的第一个环节。它负责将各种格式的原始文档（TXT、Markdown、HTML 等）转换为纯净的文本，去除格式标记和无关内容。

在实际的企业知识库中，文档格式往往非常多样：技术团队可能使用 Markdown 编写文档，产品团队可能使用 Word 文档，运营团队可能保存了 HTML 格式的网页内容。文档解析器需要能够处理这些不同格式，将它们统一转换为纯净的文本，以便后续的分块和检索。

class DocumentParser:
    """
    文档解析器：支持多种格式。
    综合了 6.2 和 6.3 节的文档解析知识。
    """

    @staticmethod
    def parse_markdown(filepath: str) -> str:
        """解析 Markdown 文件"""
        text = Path(filepath).read_text(encoding="utf-8")
        text = re.sub(r"```[\s\S]*?```", "", text)
        text = re.sub(r"!\[.*?\]\(.*?\)", "", text)
        text = re.sub(r"\[(.*?)\]\(.*?\)", r"\1", text)
        text = re.sub(r"^#{1,6}\s+", "", text, flags=re.MULTILINE)
        text = text.replace("**", "").replace("*", "")
        text = re.sub(r"^>\s+", "", text, flags=re.MULTILINE)
        return text.strip()

    @classmethod
    def parse(cls, filepath: str) -> Optional[Document]:
        """根据扩展名自动解析"""
        ext = Path(filepath).suffix.lower()
        parsers = {
            ".txt": cls.parse_text,
            ".md": cls.parse_markdown,
            ".html": cls.parse_html,
        }
        parser = parsers.get(ext)
        if parser is None:
            return None
        text = parser(filepath)
        return Document(doc_id=Path(filepath).stem, text=text)

三、文本分块模块

文本分块将长文档切分为固定大小的块，每个块独立编码和检索。我们使用递归分块策略，先按段落分割，对超过目标大小的段落再按句子分割。

分块大小是影响检索效果的关键参数。分块过大，Embedding 会丢失细粒度语义，检索精度下降；分块过小，单个块可能缺乏足够的上下文信息。经验上，500-800 字符是一个比较合适的范围，但具体数值应该根据文档类型和实际效果进行调整。

class TextChunker:
    """
    文本分块器：使用递归分块策略。
    综合了 6.4 节的分块知识。
    """

    def __init__(self, chunk_size: int = 500, overlap: int = 50):
        self.chunk_size = chunk_size
        self.overlap = overlap

    def chunk(self, doc: Document) -> List[Chunk]:
        """将文档切分为文本块"""
        paragraphs = re.split(r"\n\n+", doc.text)
        current_chunk = []
        current_length = 0
        chunks = []

        for para in paragraphs:
            if current_length + len(para) > self.chunk_size and current_chunk:
                chunks.append(Chunk(...))
                current_chunk = []
                current_length = 0
            current_chunk.append(para)
            current_length += len(para)

        return chunks

四、向量检索模块

向量检索模块将文本块编码为向量，存储在向量索引中。查询时，将用户问题也编码为向量，通过余弦相似度找到最相似的文本块。这部分综合了模块五的向量检索知识。

向量检索是整个 RAG 系统的核心环节。检索质量直接决定了后续回答的准确性。为了提高检索效果，我们采用了余弦相似度作为距离度量，这是一种广泛使用的向量相似度计算方法，能够有效捕捉文本之间的语义相似性。

class SimpleVectorIndex:
    """
    简易向量索引：使用余弦相似度进行检索。
    综合了模块五的向量检索知识。
    """

    def __init__(self, embedding_fn):
        self.embedding_fn = embedding_fn
        self.chunks = []
        self.vectors = []

    def search(self, query: str, top_k: int = 5) -> List[SearchResult]:
        """检索最相关的文本块"""
        query_vector = self.embedding_fn(query)
        scores = []
        for i, vec in enumerate(self.vectors):
            score = self._cosine_similarity(query_vector, vec)
            scores.append((i, score))
        scores.sort(key=lambda x: x[1], reverse=True)
        return [SearchResult(...) for idx, score in scores[:top_k]]

五、重排序与上下文管理

检索到的结果需要重排序和上下文管理，确保最相关的文档排在最前面，并去除噪声。这部分综合了 6.6 和 6.7 节的知识。

重排序的目的是纠正向量检索的排序偏差。向量检索基于嵌入向量的余弦相似度，这种度量方式虽然能够捕捉语义相似性，但在精确匹配方面不如交叉编码器。因此，我们在向量检索之后增加一层重排序，进一步提高排序质量。

上下文管理则负责将重排序后的结果转换为适合 LLM 处理的格式。这包括过滤低分文档、控制上下文长度、以及按相关性排序以确保最相关的信息在开头和结尾位置，避免 Lost in the Middle 问题。

class SimpleReranker:
    """简易重排序器：基于关键词匹配度重排序"""

    def rerank(self, query, results, top_k=3):
        query_words = set(query.replace(" ", ""))
        reranked = []
        for result in results:
            doc_words = set(result.text.replace(" ", ""))
            overlap = len(query_words & doc_words) / max(len(query_words), 1)
            combined = result.score * 0.5 + overlap * 0.5
            reranked.append(SearchResult(..., score=combined))
        reranked.sort(key=lambda x: x.score, reverse=True)
        return reranked[:top_k]


class ContextManager:
    """上下文管理器：过滤、压缩、重排序"""

    def process(self, query, results):
        filtered = [r for r in results if r.score >= self.threshold]
        filtered.sort(key=lambda x: x.score, reverse=True)
        context_parts = []
        for r in filtered:
            context_parts.append(f"[文档 {r.doc_id}] {r.text}")
        return "\n\n".join(context_parts)

六、Prompt 构建与 LLM 生成

最后，将检索到的上下文和用户问题组合为 Prompt，发送给 LLM 生成回答。这部分综合了 6.1 节的 RAG 流程知识。

Prompt 的设计对回答质量有重要影响。一个好的 RAG Prompt 应该明确告诉 LLM：你是基于参考资料回答问题的，如果资料中没有答案，应该直接说明，而不是编造答案。这种"防幻觉"的 Prompt 设计是 RAG 系统中非常关键的一环。

在实际项目中，Prompt 的设计需要反复迭代和测试。不同的 LLM 模型对 Prompt 的响应方式可能不同，需要根据具体模型调整 Prompt 的措辞和结构。

class PromptBuilder:
    """Prompt 构建器"""

    RAG_PROMPT = """你是一个专业的知识库助手。请根据以下参考资料回答用户的问题。

参考资料：
{context}

问题：{question}

请根据参考资料提供准确、简洁的回答。"""

    @classmethod
    def build(cls, question: str, context: str) -> str:
        return cls.RAG_PROMPT.format(context=context, question=question)

七、完整的知识库问答系统

将以上所有模块组合起来，就形成了完整的知识库问答系统。这个系统封装了从文档导入到问答生成的完整流程，用户只需要提供文档路径和问题，就能获得基于知识库的回答。

系统设计采用了模块化架构，每个组件都是独立的，可以单独替换和升级。这种设计使得系统具有良好的可扩展性和可维护性。在实际项目中，可以根据需求替换任何一个组件，而不影响其他部分。

知识库问答系统的核心价值在于：它能够将企业的非结构化知识资产转化为可交互的智能服务。无论是技术文档、产品手册还是内部规范，都可以通过这个系统被快速检索和问答，大幅提升知识获取的效率。

class KnowledgeBaseQA:
    """
    企业知识库问答系统：综合运用所有 RAG 知识。

    完整流程：
    1. 文档加载与解析
    2. 文本分块
    3. 向量索引构建
    4. 查询 → 检索 → 重排序 → 上下文管理
    5. Prompt 构建 → LLM 生成回答
    """

    def __init__(self, embedding_fn, llm_fn=None):
        self.parser = DocumentParser()
        self.chunker = TextChunker()
        self.vector_index = SimpleVectorIndex(embedding_fn)
        self.reranker = SimpleReranker()
        self.context_manager = ContextManager()
        self.llm = llm_fn or MockLLM.generate

    def ingest(self, filepaths: List[str]):
        """导入文档到知识库"""
        for filepath in filepaths:
            doc = self.parser.parse(filepath)
            chunks = self.chunker.chunk(doc)
            self.vector_index.add_chunks(chunks)

    def query(self, question: str, top_k: int = 5) -> str:
        """查询知识库"""
        results = self.vector_index.search(question, top_k)
        reranked = self.reranker.rerank(question, results)
        context = self.context_manager.process(question, reranked)
        prompt = PromptBuilder.build(question, context)
        return self.llm(prompt)
