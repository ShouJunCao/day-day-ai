7.1 Graph RAG（Microsoft GraphRAG）

模块七：高级 RAG 技术 预计学习：50 分钟

学习目标

  • 理解传统 RAG 的局限性和 Graph RAG 的设计动机
  • 掌握知识图谱构建的核心流程
  • 学会社区检测和层次化摘要的方法
  • 能够对比 Graph RAG 与传统 RAG 的优劣

一、传统 RAG 的局限性

传统 RAG 系统基于向量检索来查找相关文档片段。这种方法在处理"这个文档说了什么"类型的问题时表现良好，但在面对需要综合分析的问题时存在明显的局限性。

主要问题包括：第一，缺乏全局理解。向量检索只能找到局部匹配的文本片段，无法理解文档之间的关联和整体结构。第二，无法回答跨文档问题。当答案需要综合多个文档的信息时，传统 RAG 只能独立检索每个片段，难以整合。第三，无法发现隐含关系。向量检索只能基于语义相似度匹配，无法发现实体之间的深层关系。

Microsoft 在 2024 年提出的 Graph RAG 正是为了解决这些问题。它将知识图谱与 RAG 结合，通过构建文档的知识图谱，实现全局理解和综合分析能力。这项技术的核心创新在于：不仅关注文档中的文本内容，还关注实体之间的关系结构，从而实现对数据集的整体把握。

从技术路线来看，Graph RAG 代表了 RAG 技术从"基于相似度匹配"向"基于结构理解"的演进方向。它不仅提升了检索质量，还为复杂分析和全局摘要提供了可能。这使得 Graph RAG 成为当前高级 RAG 技术中最受关注的方向之一。

二、Graph RAG 的核心架构

Graph RAG 的核心思想是将文档转换为知识图谱，然后通过图谱的结构信息来增强检索和回答生成。整个流程分为两个阶段：索引阶段和查询阶段。

三、知识图谱构建

知识图谱构建是 Graph RAG 的第一步。它从文档中提取实体和关系，构建一个以实体为节点、以关系为边的图结构。

实体提取可以使用命名实体识别（NER）模型，也可以使用 LLM。Microsoft 的 GraphRAG 使用 LLM 来提取实体，因为 LLM 能够更灵活地识别各种类型的实体，包括专业术语和领域概念。

关系提取则需要判断两个实体之间是否存在关联。最简单的方法是共现分析：如果两个实体在同一段落或同一文档中同时出现，认为它们之间存在关系。更高级的方法是使用关系抽取模型，识别具体的关系类型（如"属于"、"开发"、"使用"等）。

3.1 代码实现

07_advanced_rag/01_graph_rag/graph_rag.py
class KnowledgeGraphBuilder:
    """
    知识图谱构建器：从文档中提取实体和关系。

    原理：
    1. 从文本中提取命名实体
    2. 识别实体之间的关系
    3. 构建图结构（节点=实体，边=关系）
    4. 使用社区检测算法发现实体集群
    """

    def __init__(self):
        self.adjacency: Dict[str, set] = defaultdict(set)
        self.entities: Dict[str, Entity] = {}
        self.relationships: List[Relationship] = []

    def extract_entities(self, text: str) -> List[Entity]:
        """从文本中提取实体"""
        entities = []
        patterns = {
            "technology": r"(?:Transformer|BERT|GPT|RAG|LLM)",
            "organization": r"(?:Google|OpenAI|Microsoft|Meta)",
            "concept": r"(?:注意力机制|自注意力|预训练|微调)",
        }
        for entity_type, pattern in patterns.items():
            for match in re.finditer(pattern, text):
                name = match.group()
                if name not in self.entities:
                    entity = Entity(name=name, entity_type=entity_type)
                    entities.append(entity)
                    self.entities[name] = entity
        return entities

    def extract_relationships(self, text, entities):
        """基于共现分析提取关系"""
        paragraphs = re.split(r"\n\n+", text)
        for para in paragraphs:
            para_entities = [e for e in entities if e.name in para]
            for i in range(len(para_entities)):
                for j in range(i + 1, len(para_entities)):
                    source, target = para_entities[i].name, para_entities[j].name
                    self.adjacency[source].add(target)
                    self.adjacency[target].add(source)
                    self.relationships.append(Relationship(
                        source=source, target=target,
                        description="在文档中共同出现",
                    ))

四、社区检测与层次化摘要

社区检测是 Graph RAG 的关键创新之一。它使用 Louvain 等社区检测算法，将知识图谱中的实体划分为多个社区（集群）。每个社区包含一组紧密相关的实体。

4.1 社区检测算法

Louvain 算法是一种贪婪优化算法，通过最大化模块度（Modularity）来发现图中的社区结构。模块度衡量的是社区内部连接密度与随机期望连接密度之间的差异。模块度越高，社区划分质量越好。

4.2 层次化摘要

Graph RAG 的创新之处在于为每个社区生成摘要。它使用 LLM 为每个社区生成一段简洁的描述，概括该社区中所有实体的核心信息。然后，这些社区摘要又被组织为更高层次的摘要，形成一个层次化的知识结构。

这种层次化摘要的优势在于：当用户提出一个高层次的问题（如"这份数据集主要说了什么"）时，系统可以使用顶层摘要来回答；当用户提出具体的问题时，系统可以定位到相关社区，使用更细粒度的信息来回答。

4.3 代码实现

class KnowledgeGraphBuilder:
    def detect_communities(self) -> List[Community]:
        """使用 Louvain 算法进行社区划分"""
        if len(self.adjacency) == 0:
            return []

        try:
            from community import best_partition
            import networkx as nx
            temp_g = nx.Graph()
            for node, neighbors in self.adjacency.items():
                for nb in neighbors:
                    temp_g.add_edge(node, nb)
            partition = best_partition(temp_g)

            community_map = {}
            for node, comm_id in partition.items():
                community_map.setdefault(comm_id, []).append(node)

            communities = []
            for comm_id, members in community_map.items():
                community = Community(
                    community_id=comm_id,
                    entities=members,
                    summary=f"社区 {comm_id}: 包含 {len(members)} 个实体",
                )
                communities.append(community)
            return communities

        except ImportError:
            return [Community(
                community_id=0,
                entities=list(self.adjacency.keys()),
                summary="默认社区",
            )]

五、Graph RAG 查询

Graph RAG 的查询流程与传统 RAG 有本质不同。它不是在文档片段中搜索相似内容，而是在知识图谱中定位相关实体，然后通过图谱遍历找到关联信息，最后结合社区摘要生成回答。

5.1 查询步骤

  1. 实体匹配：从用户问题中提取与知识图谱中实体匹配的关键词
  2. 图谱遍历：从匹配到的实体出发，遍历其邻居节点，收集相关信息
  3. 社区检索：找到包含这些实体的社区，获取社区摘要
  4. 上下文构建：将实体描述、关系信息和社区摘要组合为上下文
  5. LLM 生成：将上下文和问题发送给 LLM 生成回答

5.2 代码实现

class GraphRAGQueryEngine:
    """Graph RAG 查询引擎：基于知识图谱的增强检索"""

    def __init__(self, graph_builder, llm_fn=None):
        self.adjacency = graph_builder.adjacency
        self.entities = graph_builder.entities
        self.communities = graph_builder.communities

    def query(self, question: str) -> GraphRAGResult:
        # 1. 实体匹配
        query_entities = self._find_relevant_entities(question)
        # 2. 图谱遍历
        neighbors = self._find_neighbors(query_entities)
        # 3. 社区检索
        related = self._find_related_communities(query_entities)
        # 4. 上下文构建
        context = self._build_context(query_entities, neighbors, related)
        # 5. LLM 生成
        answer = self.llm_fn(question, context)
        return GraphRAGResult(answer=answer, entities_used=query_entities)

六、Graph RAG vs 传统 RAG 全面对比

Graph RAG 与传统 RAG 在技术路线和适用场景上有本质区别。传统 RAG 关注的是"如何在文档中找到相关内容"，而 Graph RAG 关注的是"如何理解文档集合的整体结构和关联"。两种技术并非互斥关系，而是互补关系。

检索方式 向量相似度 图谱遍历 + 向量
上下文构建 Top-K 文档片段 实体 + 关系 + 社区摘要
全局理解 弱（局部匹配） 强（全局结构）
复杂查询 一般 优秀
计算开销 低 高（图谱构建 + LLM 摘要）
适用场景 文档问答 综合分析/摘要/跨文档推理
数据更新 增量索引 需要重建图谱

七、Graph RAG 的适用场景

Graph RAG 并非在所有场景下都优于传统 RAG。它的优势主要体现在需要全局理解和综合分析的场景中。在实际项目中，应该根据具体的业务需求和技术条件来选择合适的方案。

  • 文档摘要：当需要回答"这份数据集主要说了什么"时，Graph RAG 可以通过社区摘要提供全面的概述
  • 跨文档推理：当答案需要综合多个文档的信息时，Graph RAG 可以通过图谱遍历发现跨文档关联
  • 主题发现：当需要发现文档集合中的主要主题和子主题时，社区检测可以自动发现主题集群
  • 实体关系查询：当需要回答"X 和 Y 之间有什么关系"时，Graph RAG 可以直接在图谱中找到路径
⚠️ 成本考虑

Graph RAG 的构建成本显著高于传统 RAG。实体提取、关系提取和社区摘要都需要调用 LLM，对于大规模文档集合来说，这可能是一笔不小的开销。建议先评估业务需求，只有在传统 RAG 无法满足全局理解需求时，才考虑使用 Graph RAG。

八、小结

Graph RAG 是 Microsoft 提出的一种将知识图谱与 RAG 结合的高级检索技术。它通过构建知识图谱、进行社区检测和层次化摘要，实现了传统 RAG 无法提供的全局理解和综合分析能力。

Graph RAG 的核心创新在于：使用知识图谱来表示文档的结构信息，使用社区检测来发现文档中的主题集群，使用层次化摘要来提供不同粒度的理解。这使得 Graph RAG 在文档摘要、跨文档推理和主题发现等场景下表现优异。

然而，Graph RAG 的构建成本较高，需要调用 LLM 进行实体提取、关系提取和社区摘要。在实际应用中，应该根据业务需求权衡收益和成本，选择合适的方案。对于大多数常规文档问答场景，传统 RAG 已经足够；只有当需要全局理解能力时，才值得投入 Graph RAG 的额外成本。

总的来说，Graph RAG 代表了 RAG 技术从"基于相似度匹配"向"基于结构理解"的重要演进方向，值得持续关注和研究。在实际项目中，可以先用传统 RAG 快速上线，再根据用户反馈和业务需求决定是否引入 Graph RAG 来增强全局理解能力。
