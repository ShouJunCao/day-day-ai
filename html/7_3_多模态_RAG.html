7.3 多模态 RAG（图片、表格、代码块处理）

模块七：高级 RAG 技术 预计学习：50 分钟

学习目标

  • 理解传统 RAG 在处理多模态内容时的局限性
  • 掌握图片、表格、代码块的提取和编码方法
  • 学会构建多模态检索系统
  • 了解视觉语言模型在多模态 RAG 中的应用

一、为什么需要多模态 RAG？

传统 RAG 系统只能处理纯文本内容。然而，现实世界中的文档往往包含丰富的多模态内容：技术文档中有架构图和代码示例，产品手册中有表格和图片，学术论文中有数据图表和公式。

这些多模态内容承载着大量关键信息，如果直接忽略，会导致检索结果不完整。例如，一张架构图中可能包含整个系统的组件关系，一个表格可能包含关键的性能数据对比，一段代码示例可能展示了 API 的正确用法。在技术文档中，图片、表格和代码块往往比纯文本承载了更多的信息密度。

多模态 RAG 的核心目标是：在保持纯文本检索能力的基础上，增加对图片、表格、代码块等多模态内容的理解和检索能力。当用户查询相关内容时，系统不仅能够返回相关文本，还能提供相关的图片、表格和代码。这不仅提高了检索的完整性，还提升了用户获得的信息质量。

从技术角度来看，多模态 RAG 的实现依赖于多个子技术的组合：OCR 用于图片文字提取，视觉语言模型用于图片理解，结构化解析用于表格和代码处理。这些技术的成熟使得多模态 RAG 成为可能，并在实际应用中展现出巨大的价值。

二、多模态内容处理流程

多模态 RAG 的核心是将不同类型的文档内容转换为可用于检索和生成的格式。整个处理流程分为三个阶段：解析、编码和检索。

在解析阶段，系统需要识别文档中的不同类型内容。对于 Markdown 文档，可以使用正则表达式提取图片链接、表格结构和代码块。对于 PDF 文档，则需要使用专门的解析工具（如 pdfplumber、MinerU）来提取结构化的内容。

在编码阶段，每种类型的内容都需要转换为可用于向量检索的格式。文本直接使用 Embedding 模型编码；图片通过 OCR 提取文字或使用视觉语言模型生成描述后再编码；表格通过结构化解析提取表头和数据后，转换为文本描述再编码；代码块保留完整内容并标注语言信息后编码。

在检索阶段，所有内容的向量存储在同一索引中，检索时统一计算相似度。返回结果时，除了相关文本外，还包含相关的图片、表格和代码，为用户提供完整的多模态回答。

三、图片内容处理

图片是最难处理的多模态内容，因为它包含的信息无法直接通过文本分析获取。处理图片的核心方法有两种：OCR 文字提取和视觉描述生成。

OCR（光学字符识别）用于提取图片中的文字内容。对于包含文字的图片（如截图、扫描件、图表中的标签），OCR 可以提取出大部分关键信息。常用的 OCR 工具包括 Tesseract、PaddleOCR 等。其中 PaddleOCR 对中文支持更好，适合处理中文文档中的图片。

视觉描述则使用视觉语言模型（如 BLIP、LLaVA）生成图片的文字描述。这种方法特别适合没有文字的图片（如照片、插画、架构图），能够生成语义上接近图片内容的文字描述。结合 OCR 和视觉描述，可以最大程度地提取图片中的信息。

class ImageContentExtractor:
    """
    图片内容提取器：使用 OCR 和视觉描述模型提取图片内容。

    原理：
    1. 使用 OCR 提取图片中的文字
    2. 使用视觉描述模型生成图片描述
    3. 将提取的文字和描述用于向量检索
    """

    def extract(self, image_path: str) -> dict:
        """提取图片内容"""
        # 1. OCR 提取文字
        ocr_text = self._run_ocr(image_path)

        # 2. 视觉描述
        description = self._generate_description(image_path)

        return {
            "ocr_text": ocr_text,
            "description": description,
            "image_path": image_path,
        }

四、表格内容处理

表格是一种结构化的数据格式，包含丰富的对比和分析信息。处理表格的关键是将结构化数据转换为可用于检索的文本格式，同时保留表格的结构信息。

表格处理分为三个步骤：首先解析 Markdown 或 HTML 表格，提取表头和行数据；然后生成表格摘要（列数、行数、关键信息）；最后将表格内容转换为适合检索的文本格式，同时保留原始结构以便在回答中引用。这种处理方式既保证了表格内容的可检索性，又保留了表格的结构化信息。

4.1 代码实现

class TableContentExtractor:
    """
    表格内容提取器：将表格转换为结构化文本和摘要。
    """

    def extract(self, table_content: str) -> dict:
        """提取表格内容"""
        rows = table_content.strip().split("\n")
        headers = [h.strip() for h in rows[0].split("|") if h.strip()]
        data_rows = []
        for row in rows[2:]:
            cells = [c.strip() for c in row.split("|") if c.strip()]
            if cells:
                data_rows.append(cells)

        summary = f"表格包含 {len(headers)} 列、{len(data_rows)} 行数据。"

        return {
            "headers": headers,
            "data": data_rows,
            "summary": summary,
        }

代码块在技术文档中非常常见，包含重要的实现细节和 API 用法。处理代码块的关键是保留代码的完整性和语法信息，同时将其转换为可用于检索的文本。在实际应用中，代码块的检索需要考虑编程语言的语法特征，例如函数名、类名、变量名等关键标识符。

对于不同编程语言的代码块，系统可以采用语言特定的解析器来提取关键信息。例如，Python 代码可以提取导入的模块、定义的函数和类；Java 代码可以提取包声明、接口和注解。这些结构化的信息可以增强检索的准确性。代码块的另一个挑战是如何处理跨多个文件的代码依赖关系，这需要在索引阶段建立文件间的关联关系。

5.1 代码实现

class MarkdownMultimodalParser:
    """Markdown 多模态解析器"""

    def _extract_codes(self, content: str) -> List[MultimodalContent]:
        """提取代码块"""
        codes = []
        code_pattern = r"```(\w+)?\n([\s\S]*?)```"
        for i, match in enumerate(re.finditer(code_pattern, content)):
            lang = match.group(1) or "unknown"
            code_content = match.group(2).strip()
            codes.append(MultimodalContent(
                content_id=f"code_{i}",
                content_type="code",
                content=code_content,
                metadata={"language": lang, "index": i},
            ))
        return codes

六、多模态检索

多模态检索的核心思路是：将所有内容（文本、OCR 文字、图片描述、表格摘要、代码）组合为一个搜索文本，统一编码为向量。检索时返回包含多模态内容的结果，在回答中引用相关图片、表格和代码。

七、视觉语言模型（VLM）

视觉语言模型（Vision-Language Model）是多模态 RAG 的关键技术。它能够同时理解和生成文本与图片内容，为多模态 RAG 提供了强大的底层能力。在实际应用中，VLM 不仅可以用于图片描述生成，还可以用于视觉问答、图片检索等多种任务。

主流 VLM 包括 GPT-4V、LLaVA、Qwen-VL 等。这些模型能够直接接收图片作为输入，生成文字描述、回答问题、甚至生成代码。在多模态 RAG 中，VLM 可以用于图片理解、表格解析和代码生成。

与传统 OCR 相比，VLM 的优势在于能够理解图片的整体语义，而不仅仅是提取文字。例如，对于一张架构图，VLM 能够识别出图中的组件关系和数据流向，生成结构化的描述文本。这种能力使得 VLM 成为多模态 RAG 中图片处理的首选方案。特别是 Qwen-VL 等开源模型，不仅支持中英文双语，还在图表理解和数学公式识别方面表现出色。

七、小结

多模态 RAG 将传统 RAG 的纯文本处理能力扩展到了图片、表格和代码块等多模态内容。通过 OCR 提取图片文字、视觉描述模型生成图片语义描述、结构化解析表格和代码，系统能够全面理解文档中的所有信息。这种能力对于技术文档、产品手册、学术论文等包含丰富多模态内容的场景尤为重要。

在实际应用中，建议先用 Markdown 解析器提取所有多模态内容，然后使用相应的方法处理每种类型的内容。对于图片，优先使用 OCR 提取文字；对于表格，提取结构和生成摘要；对于代码块，保留完整内容和语言信息。最后将所有内容统一编码为向量，实现多模态检索。随着视觉语言模型（VLM）的不断发展，多模态 RAG 的能力将进一步提升。未来，VLM 将能够更精确地理解图片内容，甚至直接处理图片检索和问答，为多模态 RAG 带来质的飞跃。此外，多模态 RAG 还可以与增量更新机制结合，实现动态的知识库更新和内容同步。
