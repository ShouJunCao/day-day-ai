7.7 Corrective RAG（CRAG）与 Self-RAG

模块七：高级 RAG 技术 预计学习：50 分钟

学习目标

  • 理解传统 RAG 的幻觉问题及其成因
  • 掌握 CRAG 的检索后纠正机制
  • 掌握 Self-RAG 的生成后反思机制
  • 了解两种方法的适用场景和实现差异

一、传统 RAG 的幻觉问题

传统 RAG 系统的流程是线性的：检索 → 构建 Prompt → 生成。这个流程假设检索结果一定是相关和准确的，但现实中这个假设经常被打破。当检索结果不相关或信息不足时，系统仍然会基于这些低质量的信息生成回答，从而导致幻觉。

幻觉的根源在于 LLM 的训练机制：它被训练为生成流畅连贯的文本，而不是判断信息的真实性。当缺乏可靠的外部信息时，LLM 会倾向于编造答案。在 RAG 系统中，如果检索结果质量不佳，即使 LLM 本身能力很强，也可能生成错误的内容。

自我纠正 RAG 技术的核心思想是：让系统能够自我评估检索和生成的质量，并在发现问题时自动纠正。这就像人类在回答问题后检查自己的答案是否合理一样。通过引入自我评估机制，RAG 系统能够在发现问题时主动采取纠正措施，而不是盲目地输出可能错误的内容。

目前主流的自我纠正 RAG 技术有两种：CRAG（Corrective RAG）和 Self-RAG。它们的核心区别在于纠正的时机：CRAG 在检索之后、生成之前进行纠正，而 Self-RAG 在生成之后进行纠正。两种方法各有优势，适用于不同的场景需求。在实际应用中，选择哪种方法取决于系统的主要瓶颈是检索质量还是生成质量。

二、CRAG（Corrective RAG）

CRAG 的核心思想是在检索之后、生成之前，评估检索结果的质量。如果评估结果不达标，系统会启动纠正流程，包括重写查询、联网搜索或重新检索。这种方法能够有效解决检索质量不佳导致的幻觉问题。

CRAG 的纠正策略有三种：当检索结果部分相关时，系统会精简或重写文档内容，保留有用信息去除噪声；当检索结果完全不相关时，系统会通过外部搜索获取新信息，扩展知识来源；当检索结果高度相关时，直接用于生成，无需额外处理。

在实际应用中，CRAG 的评估环节通常使用一个专门的 LLM 来判断检索结果与查询的相关性。这个评估 LLM 接收查询和检索结果作为输入，输出一个相关性评分。评分高于阈值时认为检索质量达标，低于阈值时触发纠正流程。

class CorrectiveRAG:
    """
    Corrective RAG（CRAG）：检索后纠正。

    核心思想：在生成回答之前，先评估检索结果的质量。
    - 如果相关 -> 生成回答
    - 如果不相关 -> 修正查询 / 联网搜索 -> 重新检索
    """

    def __init__(self, evaluator: RelevanceEvaluator):
        self.evaluator = evaluator
        self.max_retries = 2

    def query(self, original_query: str, documents: List[str]) -> CorrectedResult:
        steps = []
        current_query = original_query
        best_docs = documents

        for i in range(self.max_retries + 1):
            # 1. 评估检索质量
            scores = [self.evaluator.evaluate(current_query, d) for d in best_docs]
            score = max(scores) if scores else 0.0
            steps.append(f"评估: 相关性 {score:.2f}")

            # 2. 决策
            if score >= self.evaluator.threshold:
                steps.append("决策: 质量达标，生成回答")
                break

            # 3. 纠正
            if i < self.max_retries:
                current_query = self._rewrite_query(current_query, i)
                steps.append(f"纠正: 重写查询 -> '{current_query}'")
                best_docs = self._simulate_search(current_query)
                steps.append(f"重检: 获得 {len(best_docs)} 个新文档")

三、Self-RAG

Self-RAG 与 CRAG 的不同之处在于：它在生成回答之后进行反思评估，而不是在检索之后。系统会生成多个候选回答，然后对每个回答进行多维度的质量评估。这种方法能够直接检测生成质量，包括幻觉检测。

Self-RAG 的评估维度包括：相关性（回答是否与查询相关）、忠实度（回答是否忠实于检索结果，是否有幻觉）、有用性（回答是否对查询有实际帮助）。通过多维度评估，系统能够选择质量最高的回答。

在实际应用中，Self-RAG 需要训练或使用一个专门的反思模型。这个模型能够对生成的回答进行自我评估，输出各个维度的评分。虽然这种方法计算成本较高，但能够显著提升回答质量，特别是在需要高准确率的场景中。反思模型可以基于 LLM 实现，通过精心设计的 Prompt 来引导 LLM 对生成结果进行多维度评估。

3.1 代码实现

Self-RAG 的实现需要先定义一个评估器，该评估器能够对生成结果进行多维度的评分。然后系统会生成多个候选回答，并对每个回答进行评估，最后选择评分最高的回答作为最终输出。

class SelfRAG:
    """
    Self-RAG：生成后反思。

    核心思想：生成候选答案后，进行评估反思。
    评估维度：
    - Is Relevant? (相关性)
    - Is Supported? (忠实度/是否有幻觉)
    - Is Useful? (有用性)
    """

    def __init__(self, evaluator: RelevanceEvaluator):
        self.evaluator = evaluator
        self.num_candidates = 3

    def query(self, original_query: str, documents: List[str]) -> CorrectedResult:
        steps = []
        candidates = []

        # 1. 生成多个候选
        for i in range(self.num_candidates):
            candidates.append(f"[候选 {i+1}] 回答 '{original_query}'...")
            steps.append(f"生成: 候选 {i+1}")

        # 2. 反思评估
        scored = []
        for i, ans in enumerate(candidates):
            rel = self.evaluator.evaluate(original_query, ans)
            sup = self._check_support(documents, ans)
            util = min(len(ans) / 50, 1.0)
            avg = (rel + sup + util) / 3

            steps.append(f"反思: 候选 {i+1} -> "
                        f"相关 {rel:.2f} / 忠实 {sup:.2f} / 有用 {util:.2f}")
            scored.append({"text": ans, "score": avg})

        # 3. 选择最佳回答
        scored.sort(key=lambda x: x["score"], reverse=True)

        return CorrectedResult(
            query=original_query,
            final_answer=scored[0]["text"],
            steps_taken=steps,
            confidence=scored[0]["score"],
        )

四、CRAG vs Self-RAG 全面对比

CRAG 和 Self-RAG 代表了两种不同的自我纠正思路。CRAG 聚焦于改善检索质量，通过评估和纠正检索结果来间接提升生成质量；Self-RAG 聚焦于改善生成质量，通过多维度评估直接检测和筛选高质量的生成回答。两种方法各有优势，在实际应用中可以根据具体场景选择合适的方案或结合使用。

从计算成本来看，CRAG 的成本主要体现在可能的多次检索上，而 Self-RAG 的成本主要体现在多次生成和评估上。对于检索质量不稳定的场景，CRAG 更加适合，因为它能够在生成前就确保检索结果的质量。对于生成质量不稳定的场景，Self-RAG 更加适合，因为它能够直接检测生成回答中的幻觉和错误。在实际部署时，还需要考虑评估模型的选择、阈值的设定、纠正流程的超时处理等工程实践问题。

五、小结

CRAG 和 Self-RAG 代表了两种不同的自我纠正思路：CRAG 在检索后纠正，通过改善检索质量来间接改善生成质量；Self-RAG 在生成后反思，通过直接评估生成结果的质量来选择最优回答。

在实际应用中，两种方法可以结合使用：先用 CRAG 确保检索质量，再用 Self-RAG 确保生成质量。这种双重保障能够最大程度地减少幻觉，提高回答的准确性和可靠性。对于对准确率要求极高的场景，如医疗、金融等领域，建议同时采用两种方法。

CRAG 适合检索质量不稳定的场景，比如知识库覆盖不全或查询表达模糊的情况。Self-RAG 适合生成质量不稳定的场景，比如 LLM 容易编造答案或需要高准确率的场景。根据实际需求选择合适的纠正策略，能够有效提升 RAG 系统的整体质量。同时，随着评估模型的不断进步，自我纠正 RAG 的效果还会进一步提升，成为未来 RAG 系统的重要组成部分。在实际部署时，还需要考虑评估模型的选择、阈值的设定、纠正流程的超时处理等工程实践问题，这些都是确保系统稳定运行的关键因素。

此外，自我纠正 RAG 技术还面临着一些挑战：评估模型的准确性直接影响纠正效果，如果评估模型本身不够可靠，可能会导致错误的纠正决策。此外，多次评估和纠正会增加系统的延迟和计算成本，在实际应用中需要设置合理的超时和重试机制。随着大语言模型能力的不断提升，未来自我纠正 RAG 技术有望变得更加智能和高效，成为构建高可靠性 RAG 系统的重要基础设施。在企业级应用中，还需要考虑自我纠正流程的监控和日志记录，以便在出现问题时能够快速定位和修复。

5.1 评估器代码实现

07_advanced_rag/07_corrective_rag/corrective_rag.py
class RelevanceEvaluator:
    """
    相关性评估器：评估检索结果和生成结果的质量。

    评估维度：
    - 相关性：回答是否与查询相关
    - 忠实度：回答是否基于检索结果
    - 有用性：回答是否对查询有实际帮助
    """

    def __init__(self, threshold: float = 0.5):
        self.threshold = threshold

    def evaluate(self, query: str, text: str) -> float:
        """评估相关性（简化实现）"""
        q_words = set(query.lower())
        t_words = set(text.lower())
        overlap = len(q_words & t_words) / max(len(q_words), 1)
        return min(overlap * 2, 1.0)

    def is_relevant(self, query: str, text: str) -> bool:
        """判断是否相关"""
        return self.evaluate(query, text) >= self.threshold
