8.1 Function Calling 原理与完整流程

模块八：Function Calling 预计学习：50 分钟

学习目标

  • 理解 Function Calling 的核心原理和工作机制
  • 掌握工具定义规范（JSON Schema 格式）
  • 学会实现完整的 Function Calling 流程
  • 了解 Function Calling 与传统对话的区别和优势

一、什么是 Function Calling？

Function Calling（函数调用）是大语言模型的一项关键能力，它允许模型在生成回答的过程中调用外部工具或 API。通过 Function Calling，LLM 可以获取实时数据、执行计算操作、查询数据库、调用第三方服务等，从而突破纯文本生成的限制。这种能力使得 LLM 从一个纯粹的文本生成器转变为一个能够与外部世界交互的智能助手。

Function Calling 的核心思想是：当用户的问题需要外部信息或特定操作才能回答时，LLM 不直接生成回答，而是返回一个工具调用请求，由系统执行该工具调用后，再将结果返回给 LLM 生成最终回答。这个过程可以循环多次，直到 LLM 认为已经收集到足够的信息来回答问题。通过这种方式，LLM 能够在保持自然语言交互的同时，获得执行实际任务的能力。

Function Calling 与 Prompt 中的"让模型使用工具"有着本质区别。传统的 Prompt 方式是通过文本描述告诉模型如何使用工具，模型只能模拟工具调用过程，无法真正执行；而真正的 Function Calling 是由 LLM 返回结构化的工具调用指令，系统实际执行工具调用，并将结果反馈给 LLM。这种方式保证了工具调用的准确性和可靠性，避免了模型编造工具调用结果的问题。

在实际应用中，Function Calling 广泛应用于智能客服、数据分析、自动化办公等场景。例如，在智能客服中，LLM 可以通过调用订单查询工具获取用户的订单状态，而不是编造一个虚假的订单信息；在数据分析中，LLM 可以调用数据库查询工具获取最新的数据，而不是依赖训练数据中的过时信息。

二、Function Calling 与传统对话的区别

理解 Function Calling 与传统对话的区别，是掌握其原理的关键。传统对话模式下，LLM 只能基于训练数据中的知识生成回答，无法获取实时信息或执行实际操作。当用户询问"北京今天天气怎么样"时，传统对话模式的 LLM 要么根据训练数据中的历史信息给出过时答案，要么直接承认自己无法获取实时信息。

而 Function Calling 模式赋予了 LLM 与外部世界交互的能力。当用户询问同样的问题时，LLM 可以识别出需要调用天气 API 来获取实时信息，然后返回一个结构化的工具调用请求。系统执行该调用后，将实时天气数据返回给 LLM，LLM 再基于这些真实数据生成准确的回答。这种方式不仅提高了回答的准确性，还扩展了 LLM 的能力边界。

从技术实现的角度来看，Function Calling 需要三个核心组件：工具定义（告诉 LLM 有哪些可用工具）、LLM 判断（LLM 决定是否需要调用工具以及调用哪个工具）、工具执行（系统实际执行工具调用并返回结果）。这三个组件协同工作，形成了一个完整的 Function Calling 闭环。

维度传统对话Function Calling
数据来源仅训练数据训练数据 + 实时 API
计算能力LLM 估算（可能不准确）精确计算工具
工具使用无法使用外部工具可调用多种工具
幻觉风险较高（可能编造数据）较低（有实际来源）
适用场景通用对话、创意写作任务执行、数据分析

三、工具定义规范

在 Function Calling 中，工具定义是告诉 LLM 有哪些可用工具以及每个工具的参数格式。工具定义使用 JSON Schema 格式，包含工具名称、描述和参数结构。LLM 根据这些定义来决定是否需要调用某个工具以及如何构造调用参数。

工具定义的质量直接影响 LLM 的调用准确率。一个好的工具定义应该包含：清晰的工具名称（易于理解）、详细的工具描述（说明工具的功能和使用场景）、准确的参数定义（包括参数类型、描述和必填项）。如果工具定义不够清晰，LLM 可能无法正确判断何时调用该工具，或者生成的调用参数不正确。

3.2 工具注册表实现

工具注册表是 Function Calling 系统的核心组件之一。它负责管理所有可用工具的定义和实现，提供统一的接口供 LLM 引擎调用。通过注册表，我们可以方便地添加、删除和修改工具，而不需要修改 LLM 引擎的代码。

08_function_calling/01_function_calling_principle/function_calling.py
class ToolRegistry:
    """
    工具注册表：管理可用工具的定义和实现。
    """

    def __init__(self):
        self.definitions = []
        self.implementations = {}

    def register(self, name, description, parameters, func):
        """注册一个工具"""
        self.definitions.append({
            "name": name,
            "description": description,
            "parameters": parameters,
        })
        self.implementations[name] = func

    def get_definitions(self):
        """获取所有工具定义（用于发送给 LLM）"""
        return [
            {
                "type": "function",
                "function": {
                    "name": d["name"],
                    "description": d["description"],
                    "parameters": d["parameters"],
                }
            }
            for d in self.definitions
        ]

    def execute(self, tool_name, arguments):
        """执行工具调用"""
        if tool_name not in self.implementations:
            return f"错误: 未知工具 '{tool_name}'"
        return self.implementations[tool_name](**arguments)

四、完整流程实现

Function Calling 的完整流程包含六个步骤：用户发送查询、LLM 判断是否需要调用工具、如果需要则返回工具调用请求、系统执行工具调用、将工具结果返回给 LLM、LLM 生成最终回答。这个流程可以循环多次，直到 LLM 认为已经收集到足够的信息。

在每次迭代中，引擎首先将当前的消息历史（包括用户查询、之前的工具调用和工具结果）发送给 LLM。LLM 根据工具定义和消息历史判断是否需要调用工具。如果需要，LLM 返回一个包含工具名称和参数的结构化调用请求。引擎解析这个请求，执行对应的工具调用，并将工具结果以 tool 角色的消息添加到消息历史中。然后进入下一轮迭代，LLM 再次判断是否需要继续调用工具。

当 LLM 认为已经收集到足够的信息时，它不会再返回工具调用请求，而是直接生成最终回答。此时引擎结束循环，将最终回答返回给用户。这种设计使得 Function Calling 能够处理复杂的多步任务，例如先查询天气、再查询交通状况、最后综合生成出行建议。

class FunctionCallingEngine:
    """Function Calling 引擎"""

    def __init__(self, registry, llm_fn=None):
        self.registry = registry
        self.llm_fn = llm_fn
        self.max_tool_calls = 5

    def execute(self, user_query):
        """执行完整的 Function Calling 流程"""
        messages = [Message(role="system", content="你是一个有帮助的助手。")]
        messages.append(Message(role="user", content=user_query))
        tool_calls_made = []

        for _ in range(self.max_tool_calls):
            # 1. 调用 LLM
            response = self._call_llm(messages)

            # 2. 判断是否有工具调用
            if response.get("tool_calls"):
                for tc in response["tool_calls"]:
                    tool_call = ToolCall(
                        tool_name=tc["function"]["name"],
                        arguments=json.loads(tc["function"]["arguments"]),
                    )
                    # 3. 执行工具
                    result = self.registry.execute(
                        tool_call.tool_name,
                        tool_call.arguments,
                    )
                    tool_call.result = result
                    tool_calls_made.append(tool_call)
                    # 4. 添加工具结果到消息
                    messages.append(Message(
                        role="tool",
                        content=result,
                        tool_call_id=tc["id"],
                    ))
            else:
                # 5. LLM 生成最终回答
                return FunctionCallingResult(
                    messages=messages,
                    final_answer=response.get("content", ""),
                    tool_calls_made=tool_calls_made,
                )

五、工具调用的数据结构

Function Calling 涉及三种核心消息类型：用户消息（user）、助手消息（assistant）和工具消息（tool）。每种消息类型有特定的字段和用途，理解这些数据结构是实现 Function Calling 的基础。

消息角色核心字段用途
systemcontent系统提示词，设定助手行为
usercontent用户输入的查询
assistantcontent, tool_calls助手回复或工具调用请求
toolcontent, tool_call_id工具执行结果

六、小结

Function Calling 是大语言模型从"纯文本生成"走向"任务执行"的关键桥梁。通过结构化的工具定义和标准化的消息格式，LLM 能够在需要时调用外部工具获取实时信息，从而提供更加准确和实用的回答。这种能力使得 LLM 从一个纯粹的文本生成器转变为一个能够与外部世界交互的智能助手，极大地扩展了其应用场景和能力边界。

理解 Function Calling 的核心原理——即 LLM 判断是否需要调用工具、返回结构化的调用请求、系统执行调用、结果返回给 LLM 生成最终回答——是掌握后续工具定义规范、多工具编排、错误处理等高级内容的基础。在实际项目中，需要根据业务需求设计合适的工具定义，确保 LLM 能够准确理解每个工具的功能和使用场景。
