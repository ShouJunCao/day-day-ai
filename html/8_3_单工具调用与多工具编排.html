8.3 单工具调用与多工具编排

模块八：Function Calling 预计学习：50 分钟

学习目标

  • 掌握单工具调用的执行流程和结果处理
  • 理解四种多工具编排模式及其适用场景
  • 学会实现顺序、并行、链式、条件编排
  • 能够设计复杂的多工具编排方案

一、单工具调用

单工具调用是 Function Calling 的基础单元。当 LLM 识别出需要调用工具时，它会返回一个结构化的工具调用请求，包含工具名称和参数。系统执行该调用后，将结果返回给 LLM。这个过程看似简单，但在实际实现中需要考虑多个方面。

单工具调用的核心步骤包括：解析 LLM 返回的工具调用请求（提取工具名称和参数）、验证参数是否符合工具的 Schema 定义、执行工具调用并获取结果、将结果格式化为 LLM 可理解的消息格式返回。每一个步骤都需要仔细处理，确保数据格式正确且错误能够被妥善处理。

在实际应用中，单工具调用是最常见的场景。例如，用户询问"北京今天天气怎么样"，LLM 返回一个调用 get_weather 工具的请求，系统执行调用后返回"晴，25°C"。这个过程只需要调用一个工具，逻辑简单清晰。但当任务需要多个工具协同完成时，就需要引入多工具编排。

1.1 核心实现

08_function_calling/03_tool_orchestration/tool_orchestration.py
class SingleToolCaller:
    """单工具调用：执行单个工具调用并返回结果"""

    def __init__(self, registry: SimpleToolRegistry):
        self.registry = registry

    def call(self, tool_name: str, arguments: Dict[str, Any]) -> ToolCall:
        """执行单个工具调用"""
        result = self.registry.execute(tool_name, arguments)
        success = not result.startswith("错误:")
        return ToolCall(
            tool_name=tool_name,
            arguments=arguments,
            result=result,
            success=success,
            error="" if success else result,
        )

二、多工具编排模式

在实际应用中，很多任务需要多个工具协同完成。例如，生成一份包含天气、交通、新闻的综合日报，需要调用多个不同的工具。多工具编排就是管理这些工具调用顺序和依赖关系的机制。通过合理的编排，我们可以将复杂的任务分解为多个简单的工具调用步骤，每个步骤只关注自己的职责，最终组合成完整的解决方案。

我们定义了四种基本的编排模式：顺序模式（Sequential）按预定顺序依次执行每个步骤，适合有明确依赖关系的多步任务；并行模式（Parallel）同时执行所有步骤，适合相互独立的多路查询；链式模式（Chained）将前一步的输出作为下一步的输入，适合数据流水线处理；条件模式（Conditional）根据前一步的结果动态选择后续步骤，适合分支决策场景。

选择合适的编排模式取决于任务的特点：如果各步骤之间有严格的前后依赖关系，使用顺序模式；如果各步骤相互独立且希望提高执行效率，使用并行模式；如果数据需要在步骤之间流动转换，使用链式模式；如果执行路径需要根据中间结果动态决定，使用条件模式。在实际项目中，这些模式可以组合使用，例如先并行查询多个数据源，然后将结果汇总后进行条件判断，最后根据不同的判断结果执行不同的后续操作。

编排模式执行方式步骤依赖典型场景
顺序 Sequential依次执行前一步完成后执行下一步查询天气 → 格式化 → 通知
并行 Parallel同时执行步骤之间无依赖同时查询多个城市天气
链式 Chained输出传下一步上一步输出作为下一步输入获取数据 → 转换 → 存储
条件 Conditional按条件选择根据中间结果选择路径库存充足则发货，不足则补货

三、顺序编排

顺序编排是最简单的多工具编排模式。它按照预定的顺序依次执行每个步骤，每一步等待前一步完成后才开始执行。如果某一步执行失败，后续步骤将不再执行。这种模式适合有明确依赖关系的多步任务，例如先查询天气数据，然后将数据格式化为可读文本，最后将格式化后的文本发送给用户。

3.1 核心实现

08_function_calling/03_tool_orchestration/tool_orchestration.py
def _run_sequential(self, steps, context):
    """顺序执行：步骤依次执行"""
    results = {}
    for i, step in enumerate(steps):
        tool_name = step["tool"]
        args = self._resolve_args(step.get("args", {}), context, results)
        call = self.caller.call(tool_name, args)
        results[f"step_{i+1}"] = {
            "tool": tool_name,
            "args": args,
            "result": call.result,
            "success": call.success,
        }
        if not call.success:
            results[f"step_{i+1}"]["error"] = call.error
            break  # 失败时停止
    return results

四、并行编排

并行编排同时执行所有步骤，适合相互独立的多路查询。例如，同时查询北京、上海、广州三个城市的天气，这三个查询之间没有依赖关系，可以并行执行以提高效率。在实际生产环境中，并行编排通常使用线程池或异步 IO 实现，而不是简化版的顺序模拟。

并行编排的关键在于确保各步骤之间没有依赖关系。如果某个步骤需要另一个步骤的结果作为输入，就不能使用并行模式。此外，并行编排的结果汇总需要将所有步骤的结果合并返回，便于后续处理。

五、链式编排

链式编排将前一步的输出作为下一步的输入，形成一条数据处理流水线。这种模式适合数据需要多次转换的场景，例如先获取原始天气数据（JSON 格式），然后将其格式化为可读文本，最后将文本发送给用户通知。

在链式编排中，每一步的输出格式需要与下一步的输入格式兼容。如果格式不匹配，需要在步骤之间添加转换逻辑。参数解析器支持 ${step_N} 语法来引用前一步的结果，使得数据传递更加灵活。

5.1 核心实现

08_function_calling/03_tool_orchestration/tool_orchestration.py
def _run_chained(self, steps, context):
    """链式传递：前一步输出作为下一步输入"""
    results = {}
    chain_input = {}

    for i, step in enumerate(steps):
        tool_name = step["tool"]
        args = self._resolve_args(step.get("args", {}), context, results)
        # 使用显式声明的参数，不自动合并

        call = self.caller.call(tool_name, args)
        results[f"step_{i+1}"] = {
            "tool": tool_name,
            "args": args,
            "result": call.result,
            "success": call.success,
        }

        if call.success:
            try:
                parsed = json.loads(call.result)
                if isinstance(parsed, dict):
                    chain_input = parsed
                else:
                    chain_input = {"output": call.result}
            except (json.JSONDecodeError, TypeError):
                chain_input = {"output": str(call.result)}

        if not call.success:
            results[f"step_{i+1}"]["error"] = call.error
            break

    return results

六、条件编排

条件编排根据前一步的结果动态选择后续执行路径。这种模式适合需要根据中间结果做出决策的场景。例如，在电商系统中，先检查库存，如果库存充足则直接发货，如果库存不足则触发补货流程。条件编排使得系统能够根据不同的情况采取不同的处理策略。

条件编排的实现依赖于条件评估器，它根据预设的条件表达式和当前上下文来决定是否执行某个步骤。在我们的简化实现中，条件评估通过检查上下文中指定键的值是否匹配来实现。在实际生产环境中，可以使用更复杂的条件表达式引擎。

七、小结

单工具调用是 Function Calling 的基础单元，多工具编排则是将多个工具调用组合起来完成复杂任务的机制。通过顺序、并行、链式、条件四种基本编排模式，我们可以灵活应对各种复杂的工具调用场景。

在实际项目中，编排模式的选择取决于任务的特点：有明确依赖关系的多步任务使用顺序模式，相互独立的多路查询使用并行模式，数据需要逐步转换的场景使用链式模式，需要根据中间结果动态决策的场景使用条件模式。理解这些模式的特点和适用场景，是设计高效可靠工具调用方案的关键。
