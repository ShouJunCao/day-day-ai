8.5 工具权限控制与安全沙箱（Docker、E2B）

模块八：Function Calling 预计学习：50 分钟

学习目标

  • 理解工具调用的安全风险和威胁场景
  • 掌握基于角色的权限控制模型
  • 学会使用 Docker 和 E2B 实现工具调用沙箱
  • 能够设计完整的工具权限控制方案

一、为什么需要权限控制和安全沙箱？

在 Function Calling 系统中，工具调用可能带来严重的安全风险。如果不对工具调用进行权限控制和安全隔离，恶意用户或错误的工具配置可能导致数据泄露、系统破坏、资源滥用等严重后果。特别是在多用户环境中，不同用户应该有不同的工具访问权限，某些敏感工具（如数据库操作、文件删除、网络请求）必须严格限制访问范围。

权限控制的核心目标是确保每个用户只能访问其角色允许的工具。我们采用基于角色的访问控制（RBAC）模型，将权限分配给角色，然后将角色分配给用户。这种间接映射的方式使得权限管理更加灵活和可扩展。例如，普通用户只能访问只读工具，编辑用户可以访问读写工具，管理员可以访问所有工具包括管理面板。

安全沙箱的核心目标是在隔离环境中执行工具调用，防止工具访问宿主机资源或执行恶意操作。沙箱提供了多层次的隔离：子进程隔离可以防止工具影响主进程，Docker 容器隔离可以防止工具访问宿主文件系统，E2B 云端沙箱可以在完全隔离的云端环境中执行工具调用。选择合适的沙箱类型取决于安全要求和性能考虑。在实际生产环境中，通常需要根据工具的危险等级选择不同的沙箱类型，对于高风险工具使用 Docker 或 E2B 沙箱，对于低风险工具可以使用子进程隔离。

二、基于角色的权限控制（RBAC）

RBAC（Role-Based Access Control）是最常用的权限模型。它将权限分配给角色，然后将角色分配给用户。这样，用户的权限由其所拥有的角色决定，而不是直接分配给用户。这种间接映射的方式使得权限管理更加灵活和可扩展，当需要修改某类用户的权限时，只需要修改角色的权限定义，所有拥有该角色的用户会自动获得新的权限。

在 Function Calling 系统中，常见的权限类型包括：READ（只读，允许查询数据）、WRITE（读写，允许修改数据）、EXECUTE（执行，允许运行命令）、NETWORK（网络访问，允许发起网络请求）、ADMIN（管理员，允许管理系统配置）。每种工具需要定义其所需的权限集合，用户必须拥有工具所需的所有权限才能调用该工具。

权限检查的流程包括：首先检查工具是否已注册，然后检查用户是否拥有工具所需的所有权限，最后检查调用频率是否超过限制。这三个检查步骤确保只有授权用户才能以合理的频率调用工具，防止权限滥用和资源耗尽。

class PermissionManager:
    """权限管理器：管理工具的访问权限"""

    def check_permission(self, user_id: str, tool_name: str) -> Dict:
        """检查用户是否有权限调用某个工具"""
        result = {"allowed": False, "reason": ""}

        # 1. 检查工具是否存在
        if tool_name not in self.tool_permissions:
            result["reason"] = f"工具 '{tool_name}' 未注册"
            return result

        # 2. 检查用户权限
        user_perms = self.user_roles.get(user_id, set())
        tool_perms = self.tool_permissions[tool_name].allowed_permissions

        # 用户必须拥有工具所需的所有权限
        if not tool_perms.issubset(user_perms):
            missing = tool_perms - user_perms
            result["reason"] = f"缺少权限: {', '.join(p.value for p in missing)}"
            return result

        # 3. 检查速率限制
        count = self.call_counts.get(tool_name, 0)
        if count >= self.tool_permissions[tool_name].rate_limit:
            result["reason"] = f"工具 '{tool_name}' 调用频率超限"
            return result

        result["allowed"] = True
        return result

三、安全沙箱

安全沙箱是在隔离环境中执行工具调用的机制。即使工具调用被授权，也应该在沙箱中执行，以防止工具访问不应访问的资源或执行危险操作。沙箱提供了额外的安全层，即使权限控制被绕过或工具本身存在漏洞，沙箱也能限制潜在的危害范围。

我们支持四种沙箱类型：无沙箱（NONE）用于开发测试环境，不进行任何隔离；子进程隔离（SUBPROCESS）将工具调用放在独立的子进程中执行，防止影响主进程；Docker 容器隔离（DOCKER）在 Docker 容器中执行工具调用，提供文件系统、网络和进程级别的隔离；E2B 云端沙箱（E2B）在云端完全隔离的环境中执行工具调用，适合多租户环境。

命令白名单是沙箱的重要安全机制。只有白名单中的命令才能被允许执行，其他命令一律拒绝。这种白名单策略可以有效防止恶意命令注入和意外执行危险操作。例如，允许 weather 和 query 命令，但拒绝 rm、curl、wget 等可能带来安全风险的命令。

class SecuritySandbox:
    """安全沙箱：在隔离环境中执行工具调用"""

    def execute_in_sandbox(self, command: str, timeout: float = 10.0) -> str:
        """在沙箱中执行命令"""
        # 1. 检查命令是否在白名单中
        base_cmd = command.split()[0] if command.split() else ""
        if self.allowed_commands and base_cmd not in self.allowed_commands:
            return f"错误: 命令 '{base_cmd}' 不在白名单中"

四、安全工具执行器

安全工具执行器将权限控制和沙箱执行整合在一起，提供了一个统一的安全执行接口。它首先检查用户权限，然后记录调用（用于限速），接着构建执行命令，最后在沙箱中执行命令。这种分层设计确保了每一步都有相应的安全检查，任何一步失败都会阻止后续执行。

4.1 核心实现

08_function_calling/05_security_sandbox/security_sandbox.py
class SecureToolExecutor:
    """安全工具执行器：结合权限控制和沙箱执行"""

    def execute(self, user_id, tool_name, arguments):
        """安全执行工具"""
        # 1. 权限检查
        perm_result = self.permission_manager.check_permission(user_id, tool_name)
        if not perm_result["allowed"]:
            return {"success": False, "error": f"权限拒绝: {perm_result['reason']}"}

        # 2. 记录调用（限速）
        self.permission_manager.record_call(tool_name)

        # 3. 构建命令
        command = self._build_command(tool_name, arguments)

        # 4. 在沙箱中执行
        max_time = self.permission_manager.tool_permissions[tool_name].max_execution_time
        result = self.sandbox.execute_in_sandbox(command, timeout=max_time)

        return {"success": True, "result": result}

五、E2B 云端沙箱

E2B 是一个专为 AI Agent 设计的云端沙箱平台。它提供了完全隔离的云端执行环境，每个沙箱实例都是独立的虚拟机，具有自己的文件系统、网络配置和进程空间。与本地 Docker 容器相比，E2B 的优势在于无需本地安装 Docker，适合 SaaS 应用和多租户场景。对于不想管理基础设施的团队来说，E2B 提供了一种开箱即用的沙箱解决方案。

使用 E2B 时，每个工具调用会在云端创建一个新的沙箱实例，执行完成后自动销毁。这种临时实例的设计确保了每次调用都在干净的环境中执行，不会受到之前调用的影响。同时，E2B 提供了丰富的 API，支持文件上传下载、命令执行、网络请求等功能，满足各种工具调用的需求。在实际项目中，可以将 E2B 与本地 Docker 沙箱结合使用，根据工具的安全等级选择不同的执行环境。

六、小结

工具权限控制与安全沙箱是构建安全 Function Calling 系统的两道关键防线。权限控制确保只有授权用户才能调用特定工具，沙箱确保工具调用在隔离环境中执行，即使工具本身存在问题也不会影响宿主系统。这两道防线相互配合，形成了完整的安全保障体系。在实际应用中，还需要结合日志审计和异常检测，对工具调用行为进行持续监控。

在实际项目中，建议采用分层安全策略：首先实施基于角色的权限控制，限制用户只能访问其角色允许的工具；其次实施速率限制，防止工具调用频率过高导致资源耗尽；然后实施命令白名单，只允许执行预定义的安全命令；最后在沙箱中执行工具调用，提供最后一层隔离保护。这种纵深防御策略能够最大程度地降低安全风险。
