8.6 主流框架对比（OpenAI、Anthropic、Qwen、Gemini）

模块八：Function Calling 预计学习：50 分钟

学习目标

  • 了解四大主流框架的 Function Calling 特性差异
  • 掌握各框架的工具定义格式和 API 调用方式
  • 学会根据项目需求选择合适的框架
  • 理解工具定义格式转换的方法

一、为什么需要框架对比？

在 Function Calling 的实际应用中，选择合适的框架是项目成功的关键因素之一。不同的框架在工具调用格式、并行支持、生态成熟度、成本和本地部署能力等方面有显著差异。了解这些差异能够帮助你在项目初期做出正确的技术选型，避免后期因为框架限制而需要重构代码。错误的框架选择可能导致开发效率低下、维护成本增加，甚至无法满足业务需求。

目前主流的 Function Calling 框架包括 OpenAI、Anthropic（Claude）、Qwen（通义千问）和 Gemini（Google）。这四个框架各有优势：OpenAI 的生态最成熟，工具调用功能最完善；Anthropic 的安全对齐优秀，上下文窗口大；Qwen 支持本地部署且中文能力强；Gemini 原生多模态且免费额度高。

在进行技术选型时，需要综合考虑项目需求：如果需要最完善的工具调用生态，选择 OpenAI；如果重视安全和长上下文，选择 Anthropic；如果需要本地部署和中文优化，选择 Qwen；如果需要多模态能力和高性价比，选择 Gemini。在实际项目中，也可以通过抽象层（如 LangChain）实现框架无关的代码，降低切换成本。对于中国团队来说，Qwen 通常是最优选择，因为它在中文理解和本地部署方面有明显优势。

二、工具定义格式对比

不同框架使用不同的格式来定义工具。理解这些格式差异是实现跨框架兼容的关键。OpenAI 使用 function 格式，包含 type、function.name、function.description 和 function.parameters 字段；Anthropic 使用 tool 格式，包含 name、description 和 input_schema 字段；Gemini 使用 function_declarations 格式，包含 name、description 和 parameters 字段；Qwen 兼容 OpenAI 格式，可以直接使用 OpenAI 的工具定义。

虽然各框架的工具定义格式有所不同，但核心思想是一致的：都需要定义工具名称、功能描述和参数结构。这种一致性使得我们可以通过格式转换器在不同框架之间转换工具定义，从而实现跨框架兼容。在实际开发中，建议先定义一套统一的内部工具格式，然后通过转换器生成各框架所需的格式，这样可以大幅降低多框架支持的复杂度。

2.1 各框架工具定义格式

class ToolFormatConverter:
    """工具调用格式转换器"""

    @staticmethod
    def to_openai(name, description, parameters):
        return {
            "type": "function",
            "function": {
                "name": name,
                "description": description,
                "parameters": parameters,
            }
        }

    @staticmethod
    def to_anthropic(name, description, parameters):
        return {
            "name": name,
            "description": description,
            "input_schema": parameters,
        }

    @staticmethod
    def to_gemini(name, description, parameters):
        return {
            "name": name,
            "description": description,
            "parameters": parameters,
        }

三、各框架详细对比

为了帮助你更直观地了解各框架的差异，我们从多个维度进行了详细对比。工具格式方面，OpenAI 使用 function 格式，Anthropic 使用 tool_use 格式，Qwen 兼容 OpenAI 格式，Gemini 使用 function_declarations 格式。并行调用方面，OpenAI 最多支持 128 个工具同时调用，Gemini 支持 64 个，Qwen 支持 10 个，而 Anthropic 早期版本不支持并行调用。本地部署方面，只有 Qwen 提供了开源模型支持本地部署，其他三个框架都是闭源服务。中文能力方面，Qwen 作为阿里巴巴开发的模型，在中文理解方面表现最优；其他三个框架的中文能力相对较弱，但也能满足基本需求。

四、API 调用示例对比

各框架的 API 调用方式有显著差异。OpenAI 和 Qwen 使用 chat.completions 端点，通过 tools 参数传递工具定义；Anthropic 使用 messages 端点，通过 tools 参数传递工具定义，但返回格式不同；Gemini 使用 generateContent 端点，通过 tools 参数传递 function_declarations。理解这些差异是实现跨框架兼容的关键。

在实际开发中，如果你需要同时支持多个框架，建议将工具定义和 API 调用逻辑分离。首先定义一套统一的工具描述格式，然后通过格式转换器将其转换为各框架所需的格式。这样可以确保工具定义的一致性，降低维护成本。同时，API 调用逻辑也应该通过适配器模式进行封装，使得切换框架时只需要修改适配器，而不需要修改业务代码。

4.1 OpenAI 格式调用

OpenAI 的 Function Calling API 是最成熟和完善的。通过 chat.completions 端点，使用 tools 参数传递工具定义，模型会根据用户查询自动决定是否需要调用工具以及调用哪个工具。如果模型决定调用工具，它会返回一个包含工具名称和参数的结构化响应，开发者需要执行工具调用并将结果返回给模型。

Python（OpenAI SDK）
from openai import OpenAI

client = OpenAI(api_key="YOUR_API_KEY")

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "北京天气？"}],
    tools=[{
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string"}
                },
                "required": ["city"],
            },
        }
    }],
)

4.2 Qwen 格式调用（兼容 OpenAI）

Qwen 的 API 调用格式与 OpenAI 完全兼容，这意味着使用 OpenAI SDK 编写的代码可以几乎无缝迁移到 Qwen。这是 Qwen 的一个重要优势，可以大幅降低从 OpenAI 迁移到 Qwen 的成本。开发者只需要修改 API 端点和认证方式，工具定义和业务逻辑代码无需修改。

Python（DashScope SDK）
from dashscope import Generation

# Qwen 兼容 OpenAI 格式
response = Generation.call(
    model="qwen-max",
    messages=[{"role": "user", "content": "北京天气？"}],
    tools=[{
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取天气",
            "parameters": {
                "type": "object",
                "properties": {"city": {"type": "string"}},
                "required": ["city"],
            },
        }
    }],
    result_format="message",
)

五、选型建议

在选择 Function Calling 框架时，建议从以下几个维度进行评估：工具生态成熟度、并行调用支持、本地部署能力、中文处理能力、多模态支持、成本预算和团队熟悉度。对于大多数中国团队，Qwen 是一个性价比很高的选择，它既支持本地部署，又有很强的中文理解能力，同时兼容 OpenAI API 格式，迁移成本低。

如果你的项目需要最强的工具调用生态和最完善的功能支持，OpenAI 是首选；如果重视安全性和长上下文处理，Anthropic 是不错的选择；如果需要本地部署和中文优化，Qwen 是最佳选择；如果需要多模态能力和高性价比，Gemini 值得考虑。在实际项目中，建议先使用抽象层（如 LangChain、LlamaIndex）封装工具调用逻辑，这样可以在不同框架之间灵活切换。

💡 实战建议

在项目初期，建议先选择单一框架进行原型验证，确认 Function Calling 的整体流程后再考虑多框架支持。如果需要同时支持多个框架，可以使用 ToolFormatConverter 这样的格式转换器来统一工具定义，减少代码重复。同时，建议将工具调用逻辑与框架 API 调用逻辑分离，这样在切换框架时只需要修改 API 适配层，而不需要修改核心业务逻辑。对于中国团队来说，建议优先考虑 Qwen，因为它的中文理解能力最强，且支持本地部署，可以在保证数据安全的同时降低 API 调用成本。

六、小结

主流 Function Calling 框架各有特点：OpenAI 生态最成熟，Anthropic 安全对齐优秀，Qwen 支持本地部署且中文能力强，Gemini 原生多模态且成本低。理解各框架的工具定义格式和 API 调用方式，是进行技术选型和跨框架兼容的基础。在实际开发中，通过格式转换器和适配器模式，可以实现跨框架兼容，降低框架切换成本。

对于大多数中国团队来说，Qwen 是一个很好的起点，因为它兼容 OpenAI 格式、支持本地部署、中文能力强。如果项目需要最强的工具调用生态，可以考虑 OpenAI。在实际项目中，建议通过抽象层实现框架无关的代码，这样在框架切换时只需要修改适配层，而不需要修改核心业务逻辑。同时，统一的工具定义格式和格式转换器可以大幅降低多框架支持的复杂度。
