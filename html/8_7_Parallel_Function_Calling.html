8.7 Parallel Function Calling（并行工具调用）

模块八：Function Calling 预计学习：50 分钟

学习目标

  • 理解并行工具调用的原理和应用场景
  • 掌握使用线程池实现并行工具调用的方法
  • 了解各框架对并行工具调用的支持情况
  • 能够设计高效的并行工具调用方案

一、什么是 Parallel Function Calling？

Parallel Function Calling（并行工具调用）是指同时调用多个工具，而不是依次调用。当用户的问题需要多个独立工具的结果时，并行调用可以显著提高响应速度。例如，用户请求"给我一份北京天气、科技新闻、AAPL 股价的综合日报"，这个请求需要调用天气 API、新闻 API 和股票 API，这三个调用之间没有依赖关系，完全可以并行执行。

并行工具调用的核心价值在于减少总响应时间。假设有 4 个工具调用，每个耗时 0.5 秒，如果顺序执行需要 2 秒，而并行执行只需要 0.5 秒（最慢的那个工具的耗时），加速比达到 4 倍。在实际生产环境中，当需要调用多个外部 API 时，并行调用可以将响应时间从数秒降低到数百毫秒，显著提升用户体验。

在 OpenAI 框架中，Parallel Function Calling 是原生支持的：当 LLM 返回多个 tool_calls 时，系统可以同时执行这些调用，然后将所有结果一起返回给 LLM。而在不支持并行的框架（如 Anthropic 早期版本）中，需要开发者自行实现并行逻辑，在客户端层面同时发起多个工具调用。

二、各框架的并行支持

不同框架对并行工具调用的支持程度差异很大。OpenAI 是最早支持并行工具调用的框架，最多支持 128 个工具同时调用；Anthropic 早期版本不支持并行调用，但新版本已经逐步支持；Qwen 兼容 OpenAI 的并行调用格式，最多支持 10 个工具并行；Gemini 支持最多 64 个并行工具调用。

在支持并行的框架中，LLM 可以一次性返回多个 tool_calls，开发者需要在客户端同时执行这些调用，然后将所有结果一起返回给 LLM。这个过程需要使用并发编程技术（如 Python 的 ThreadPoolExecutor 或 asyncio）来实现真正的并行执行。在不支持并行的框架中，开发者需要在客户端自行实现并行逻辑，即使 LLM 一次只返回一个工具调用请求。

三、并行调用实现

在 Python 中，实现并行工具调用最直接的方式是使用 concurrent.futures.ThreadPoolExecutor。线程池可以同时执行多个工具调用，每个工具调用在一个独立的线程中运行。当所有线程完成后，收集所有结果并返回。

实现并行调用的关键步骤包括：创建线程池并设置最大工作线程数、为每个工具调用提交一个任务到线程池、使用 as_completed 等待所有任务完成、收集所有任务的结果。需要注意的是，线程池的大小应该根据工具调用的特性来设置：对于 IO 密集型任务（如 API 调用），可以设置较大的线程数；对于 CPU 密集型任务，线程数应该接近 CPU 核心数。

3.1 核心实现

08_function_calling/07_parallel_function_calling/parallel_function_calling.py
from concurrent.futures import ThreadPoolExecutor, as_completed

class ParallelToolExecutor:
    """并行工具调用执行器"""

    def __init__(self, registry, max_workers=5):
        self.registry = registry
        self.max_workers = max_workers

    def execute_parallel(self, calls):
        """并行执行多个工具调用"""
        start_time = time.time()
        results = []

        with ThreadPoolExecutor(max_workers=self.max_workers) as executor:
            futures = {}
            for call_spec in calls:
                future = executor.submit(
                    self._execute_single,
                    call_spec["tool_name"],
                    call_spec.get("arguments", {}),
                )
                futures[future] = call_spec

            for future in as_completed(futures):
                call_spec = futures[future]
                tool_result = future.result()
                results.append(tool_result)

        total_time = time.time() - start_time
        return ParallelResult(calls=results, total_time=total_time)

四、异步实现（asyncio）

除了使用线程池，还可以使用 asyncio 实现异步并行调用。asyncio 的优势在于它是真正的异步 IO，不需要为每个工具调用创建一个线程，因此在大量并发工具调用时更加高效。对于 IO 密集型的工具调用（如 HTTP 请求），asyncio 是更好的选择。

在 asyncio 实现中，使用 asyncio.gather 来同时执行多个异步任务。gather 会等待所有任务完成后返回结果列表，这与 ThreadPoolExecutor 的 as_completed 不同：gather 按提交顺序返回结果，而 as_completed 按完成顺序返回。

4.1 异步实现示例

asyncio 是 Python 内置的异步编程库，通过事件循环实现高并发。与线程池相比，asyncio 不需要为每个任务创建独立的线程，因此在大量并发任务时内存占用更小、性能更好。对于 IO 密集型的工具调用（如 HTTP 请求、数据库查询），asyncio 是更好的选择。

asyncio vs ThreadPoolExecutor 对比

ThreadPoolExecutor 为每个任务创建一个线程，线程数量受限于系统资源，适合并发数量较少的场景；asyncio 使用事件循环和协程，可以在单线程中同时处理数千个并发任务，适合高并发场景。但 asyncio 要求所有 IO 操作都是异步的，需要使用 aiohttp 等异步库而不是 requests 等同步库。

Python（asyncio）
import asyncio

async def parallel_async(calls):
    """异步并行执行工具调用"""
    async def run_one(tool_name, arguments):
        # 使用 aiohttp 等异步 HTTP 库
        result = await async_execute(tool_name, arguments)
        return result

    # 同时执行所有任务
    tasks = [
        run_one(call["tool_name"], call.get("arguments", {}))
        for call in calls
    ]
    results = await asyncio.gather(*tasks)
    return results

五、错误处理与降级

并行工具调用中的错误处理比顺序调用更复杂。当一个工具调用失败时，不应该影响其他工具的执行。同时，需要有一种机制来处理部分失败的情况：如果 4 个工具中有 1 个失败，系统应该使用其余 3 个成功的结果生成回答，并告知用户有一个工具调用失败。

降级策略包括：对于失败的单个工具，使用缓存数据或默认值替代；如果大部分工具都失败，直接返回错误信息；在超时场景中，设置每个工具调用的超时时间，超时后自动标记为失败并继续执行其他工具。

场景策略处理方式
单个工具失败降级使用缓存或默认值，继续其他工具
大部分工具失败返回错误告知用户服务不可用，建议稍后重试
工具超时超时中断标记超时，使用部分结果生成回答
所有工具成功正常处理合并所有结果生成完整回答

5.1 错误处理实现

def _execute_single(self, tool_name, arguments):
    """执行单个工具调用（带超时和错误处理）"""
    start = time.time()
    try:
        # 使用 future.result(timeout=...) 实现超时
        future = executor.submit(
            self.registry.execute, tool_name, arguments
        )
        result = future.result(timeout=self.timeout)
        elapsed = time.time() - start
        return ParallelToolCall(
            tool_name=tool_name, arguments=arguments,
            result=result, success=True, execution_time=elapsed,
        )
    except TimeoutError:
        return ParallelToolCall(
            tool_name=tool_name, arguments=arguments,
            error="超时", success=False,
            execution_time=time.time() - start,
        )
    except Exception as e:
        return ParallelToolCall(
            tool_name=tool_name, arguments=arguments,
            error=str(e), success=False,
            execution_time=time.time() - start,
        )

六、性能优化建议

在实现并行工具调用时，有几个关键的性能优化点需要注意。线程池大小应该根据工具调用的类型来设置：对于 IO 密集型任务（如 HTTP 请求），可以设置较大的线程数（如 10~20）；对于 CPU 密集型任务，线程数应该接近 CPU 核心数。超时设置也很重要，每个工具调用都应该有独立的超时时间，避免一个慢速工具阻塞整个流程。

连接池复用是另一个重要的优化点。对于需要频繁调用同一个 API 的场景，应该使用连接池来复用 HTTP 连接，而不是每次调用都创建新的连接。这可以显著减少连接建立的时间开销。此外，结果缓存也是有效的优化手段：对于相同参数的工具调用，可以缓存结果，避免重复调用。

💡 实战建议

在实际项目中，建议将并行工具调用封装为一个独立的组件，包含线程池管理、超时控制、错误处理和结果缓存等功能。对于需要高并发的场景，推荐使用 asyncio 而不是 ThreadPoolExecutor，因为 asyncio 在大量并发时的性能更优。同时，建议为每个工具调用设置合理的超时时间，并在日志中记录每个工具的耗时，便于性能分析和优化。

七、小结

Parallel Function Calling 是提高工具调用效率的关键技术。通过并行执行多个独立的工具调用，可以将总响应时间从所有工具耗时之和降低到最慢工具的耗时。在支持并行的框架中，LLM 可以一次性返回多个 tool_calls，开发者需要在客户端使用线程池或 asyncio 实现真正的并行执行。对于 IO 密集型任务，推荐使用 asyncio 获得更好的并发性能；对于 CPU 密集型任务，使用 ThreadPoolExecutor 更加简单直接。

在实际项目中，并行工具调用应该与错误处理、超时控制和降级策略结合使用，确保即使部分工具调用失败，系统仍然能够返回有用的结果。同时，性能优化也是不可忽视的一环，包括线程池调优、连接池复用、结果缓存等策略。在下一节 8.8 中，我们将通过实战项目，综合运用前面学习的所有技术，构建一个完整的工具集（天气/数据库/API/文件操作）。
