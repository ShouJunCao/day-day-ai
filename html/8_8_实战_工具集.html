一、工具集整体架构

在本节实战中，我们将综合运用前面八章学习的所有技术，构建一个包含天气查询、数据库操作、API 调用、文件操作四大模块的完整工具集。这个工具集不仅实现了基本的功能调用，还包含了缓存优化、并行执行、错误处理、安全沙箱等工程实践，是一个可以直接用于生产环境的工具调用系统。

工具集采用模块化设计，每个工具都是独立的类，具有清晰的接口和职责。WeatherTool 负责天气查询和缓存，DatabaseTool 负责 SQLite 数据库操作，APITool 负责 HTTP API 调用模拟，FileTool 负责安全的文件读写操作。PracticalToolkit 作为协调器，负责将工具调用分发到具体的工具类，并支持并行执行。

这种设计的优势在于：每个工具可以独立测试和维护，新增工具只需要添加新的工具类并注册到分发器中；所有工具共享统一的错误处理和结果格式；并行执行器可以同时调用多个工具，显著提高响应速度。在实际项目中，可以将模拟的工具替换为真实的 API 调用，而核心架构保持不变。

二、天气工具

天气工具实现了天气查询和预报功能。它包含一个结果缓存机制，对于相同城市的重复查询，如果缓存未过期，直接返回缓存结果而不是重新调用 API。缓存过期时间默认为 5 分钟，可以根据实际需求调整。这种缓存策略可以显著减少 API 调用次数，降低延迟和成本。在实际生产环境中，天气数据通常每分钟更新一次，但用户的查询频率远高于数据更新频率，因此缓存命中率通常可以达到 80% 以上。

天气工具的核心设计原则是：查询结果必须包含完整的天气信息（温度、湿度、风力等），并且返回格式统一的 JSON 数据。这样其他工具或系统可以方便地解析和使用天气数据。对于未知城市，返回默认值而不是报错，确保系统的容错性。

2.1 核心实现

class WeatherTool:
    """天气查询工具"""

    def __init__(self, api_key="demo_key"):
        self.api_key = api_key
        self._cache = {}
        self._cache_ttl = 300  # 5 分钟缓存

    def get_weather(self, city):
        """获取指定城市天气"""
        now = time.time()
        if city in self._cache:
            cached_time, cached_data = self._cache[city]
            if now - cached_time < self._cache_ttl:
                return cached_data

        # 模拟 API 调用
        weather_data = {
            "北京": {"weather": "晴", "temp": 25, "humidity": 45},
            "上海": {"weather": "多云", "temp": 28, "humidity": 65},
        }
        data = weather_data.get(city, {})
        result = json.dumps({"city": city, **data}, ensure_ascii=False)
        self._cache[city] = (now, result)
        return result

三、数据库工具

数据库工具使用 SQLite 实现了一个轻量级的数据库操作接口。它提供了用户管理和订单查询功能，通过 SQL 查询可以灵活地获取数据。为了保证安全，查询操作只允许 SELECT 语句，防止恶意的数据修改操作。插入和更新操作通过专门的方法实现，使用参数化查询防止 SQL 注入攻击。

class DatabaseTool:
    """数据库操作工具（SQLite）"""

    def query(self, sql):
        """执行查询（只允许 SELECT）"""
        if not sql.strip().upper().startswith("SELECT"):
            return json.dumps({"error": "只允许 SELECT 查询"})
        try:
            cursor = self.conn.cursor()
            cursor.execute(sql)
            columns = [desc[0] for desc in cursor.description]
            rows = cursor.fetchall()
            return json.dumps({
                "columns": columns,
                "rows": [dict(zip(columns, row)) for row in rows],
            }, ensure_ascii=False)
        except Exception as e:
            return json.dumps({"error": str(e)})

四、API 工具

API 工具模拟了 HTTP API 调用的场景，包括搜索 API 和新闻 API。在实际生产环境中，这些模拟调用会被替换为真实的 HTTP 请求，使用 requests 或 aiohttp 等库发起网络请求。API 工具的设计考虑了分页、分类过滤等常见需求，返回格式统一的 JSON 数据，便于后续处理和展示。

搜索 API 模拟了搜索引擎的返回格式，包含查询关键词、结果列表和相关度评分。新闻 API 支持按分类（科技、财经等）获取新闻，并支持限制返回数量。在实际项目中，这些 API 调用需要处理网络超时、重试、认证等工程问题，可以结合 8.4 节学习的错误处理机制来实现。

五、文件操作工具

文件操作工具提供了安全的文件读写功能。为了防止路径遍历攻击，所有文件路径都会被规范化并检查是否在允许的基础目录内。读取文件时限制返回内容长度，防止大文件导致内存溢出。写入文件时自动创建缺失的目录结构，确保操作的成功率。

5.1 安全实现

08_function_calling/08_practical_toolkit/practical_toolkit.py
def read_file(self, filepath):
    """读取文件内容（带安全检查）"""
    # 防止路径遍历攻击
    real_path = os.path.realpath(
        os.path.join(self.base_dir, filepath.lstrip("/"))
    )
    if not real_path.startswith(self.base_dir):
        return json.dumps({"error": "路径遍历攻击被阻止"})

    with open(real_path, "r") as f:
        content = f.read()
    return json.dumps({
        "filepath": real_path,
        "size": len(content),
        "content": content[:1000],  # 限制长度
    }, ensure_ascii=False)

六、并行工具集执行器

PracticalToolkit 作为工具集的协调器，负责将工具调用分发到具体的工具类。它支持并行和顺序两种执行模式：并行模式使用 ThreadPoolExecutor 同时执行多个工具调用，适合独立的查询任务；顺序模式依次执行每个工具调用，适合有依赖关系的任务。通过并行执行，可以将多个工具调用的总耗时降低到最慢工具的耗时，显著提高用户体验。

在实际应用中，并行执行的优势尤为明显。当用户请求需要同时查询天气、新闻、股票等多个数据源时，如果顺序执行，总耗时是所有工具耗时之和；而并行执行时，总耗时取决于最慢的那个工具。例如，四个工具各耗时 0.5 秒，顺序执行需要 2 秒，并行执行只需要 0.5 秒，加速比达到 4 倍。这种性能提升对于响应时间敏感的应用场景（如实时客服、交互式查询）尤为重要。

6.1 核心实现

08_function_calling/08_practical_toolkit/practical_toolkit.py
class PracticalToolkit:
    """实战工具集：整合天气、数据库、API、文件操作"""

    def execute(self, tool_calls, parallel=True):
        """执行工具调用列表"""
        start_time = time.time()

        if parallel and len(tool_calls) > 1:
            results = self._execute_parallel(tool_calls)
        else:
            results = self._execute_sequential(tool_calls)

        total_time = time.time() - start_time
        success_count = sum(1 for r in results if r.success)
        summary = f"执行 {len(tool_calls)} 个工具调用，{success_count} 个成功"
        return ToolkitResult(results=results, total_time=total_time, summary=summary)

    def _execute_parallel(self, tool_calls):
        """并行执行"""
        results = []
        with ThreadPoolExecutor(max_workers=4) as executor:
            futures = {
                executor.submit(self._dispatch, call): call
                for call in tool_calls
            }
            for future in as_completed(futures):
                results.append(future.result())
        return results
