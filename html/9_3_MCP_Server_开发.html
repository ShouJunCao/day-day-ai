9.3 MCP Server 开发（Python/TypeScript SDK）

模块九：MCP 协议 预计学习：60 分钟

学习目标

  • 掌握使用 Python SDK 开发 MCP Server 的方法
  • 了解 TypeScript SDK 的开发流程和语法
  • 学会注册工具、资源和 Prompts 的装饰器用法
  • 能够独立开发一个简单的 MCP Server

一、MCP Server 开发概述

MCP Server 开发是指创建符合 MCP 协议的服务端程序，用于向 AI 客户端暴露工具、资源和 Prompts。MCP 提供了 Python 和 TypeScript 两种官方 SDK，使得开发者可以用熟悉的语言快速构建 MCP 服务。无论使用哪种语言，核心开发流程都是一致的：创建 Server 实例、注册能力（工具/资源/Prompts）、启动服务。这种统一的开发模式大幅降低了跨语言开发的门槛。

MCP SDK 的设计哲学是"约定优于配置"。通过装饰器模式，开发者只需要在函数上添加简单的注解，SDK 就会自动处理参数解析、JSON-RPC 消息格式、错误处理等底层细节。这种设计大幅降低了开发门槛，使得开发者可以专注于业务逻辑的实现，而不需要关心协议细节。开发者不需要了解 JSON-RPC 的具体消息格式，也不需要手动处理协议的序列化和反序列化。

在实际开发中，MCP Server 通常以独立进程的形式运行，通过 stdio 与客户端通信。对于需要远程访问的场景，也可以使用 SSE 或 HTTP 传输层。Server 可以是简单的单文件脚本，也可以是复杂的多模块应用程序，SDK 提供了灵活的扩展点，支持自定义中间件、日志记录和错误处理。对于生产环境的 Server，还需要考虑性能优化、安全加固、监控告警等工程实践。

二、Python SDK 开发

Python 是 MCP Server 开发的首选语言之一，因为 Python 拥有丰富的数据处理和 AI 生态系统。MCP Python SDK 提供了简洁的装饰器接口，使得开发者可以用极少的代码构建功能完整的 MCP 服务。SDK 支持 stdio、SSE 和 HTTP 三种传输层，满足不同场景的需求。对于本地开发的 Server，stdio 传输层是最常用的选择，它通过标准输入输出与客户端通信，简单高效。

Python SDK 的核心优势在于装饰器模式的使用。通过简单的注解，开发者可以将任意 Python 函数转换为 MCP 工具。SDK 会自动解析函数的参数类型和名称，生成符合 MCP 规范的输入 Schema。这种设计使得工具的开发变得极其简单，开发者只需要关注业务逻辑的实现，而不需要关心协议细节。

2.1 安装和初始化

Python（安装 MCP SDK）
# 安装 MCP Python SDK
pip install mcp

# 创建 Server 实例
from mcp.server import Server

server = Server(name="weather-server", version="1.0.0")

2.2 注册工具

工具是 MCP Server 最核心的能力。通过 @server.tool() 装饰器，可以将任意 Python 函数注册为 MCP 工具。SDK 会自动解析函数的参数类型和名称，生成符合 MCP 规范的输入 Schema。

Python（注册工具）
@server.tool(description="获取指定城市天气")
def get_weather(city: str) -> str:
    """获取指定城市天气"""
    weather_data = {
        "北京": "晴, 25°C",
        "上海": "多云, 28°C",
        "广州": "雷阵雨, 32°C"
    }
    return weather_data.get(city, "未知城市")

# SDK 自动生成的工具定义
# {
#     "name": "get_weather",
#     "description": "获取指定城市天气",
#     "inputSchema": {
#         "type": "object",
#         "properties": {
#             "city": {"type": "string", "description": "参数 city"}
#         },
#         "required": ["city"]
#     }
# }

2.3 注册资源

资源是只读的数据访问接口。通过 @server.resource() 装饰器，可以将 Python 函数注册为 MCP 资源。每个资源通过 URI 唯一标识，支持多种 MIME 类型。资源函数返回字符串内容，SDK 会将其包装为标准的 MCP 资源响应格式。

Python（注册资源）
@server.resource(
    uri="file:///docs/guide.md",
    name="用户指南",
    description="MCP 用户使用指南",
    mime_type="text/markdown"
)
def read_guide() -> str:
    """读取用户指南"""
    return """# MCP 用户指南
欢迎使用 MCP 协议！

## 快速开始
1. 安装 MCP SDK
2. 创建 Server 实例
3. 注册工具和资源
4. 启动服务"""

2.4 注册 Prompts

Prompts 是可复用的提示词模板。通过 @server.prompt() 装饰器，可以将 Python 函数注册为 MCP Prompt。Prompt 函数接受参数并返回填充后的模板内容，SDK 会将其转换为标准的 MCP 消息格式。

Python（注册 Prompts）
@server.prompt(description="生成天气报告")
def weather_report(city: str, days: int = 3) -> str:
    """生成天气报告 Prompt"""
    return f"""请生成{city}的天气报告，包括以下内容：

1. 当前天气状况
2. 未来{days}天天气预报
3. 空气质量指数
4. 出行建议

请使用友好的语气，提供实用的建议。"""

三、TypeScript SDK 开发

TypeScript 是 MCP Server 开发的另一个重要语言选择。TypeScript SDK 提供了类型安全的开发体验，特别适合需要严格类型检查的大型项目。TypeScript SDK 与 Python SDK 功能对等，但在语法和开发体验上有所不同。TypeScript 的强类型系统可以在编译阶段捕获大部分错误，减少运行时异常的发生。

TypeScript SDK 使用请求处理器模式而不是装饰器模式。开发者需要显式地注册每个请求类型的处理器，包括工具列表、工具调用、资源列表、资源读取等。虽然代码量稍多，但这种模式提供了更大的灵活性和控制力。对于需要精细控制请求处理流程的场景，TypeScript SDK 是更好的选择。

3.1 安装和初始化

TypeScript（安装 MCP SDK）
// 安装 MCP TypeScript SDK
npm install @modelcontextprotocol/sdk

// 创建 Server 实例
import { Server } from "@modelcontextprotocol/sdk/server";

const server = new Server(
    { name: "weather-server", version: "1.0.0" },
    { capabilities: { tools: {}, resources: {}, prompts: {} } }
);

3.2 注册工具

TypeScript（注册工具）
// 注册工具列表
server.setRequestHandler(ListToolsRequestSchema, async () => {
    return {
        tools: [{
            name: "get_weather",
            description: "获取指定城市天气",
            inputSchema: {
                type: "object",
                properties: {
                    city: { type: "string", description: "城市名称" }
                },
                required: ["city"]
            }
        }]
    };
});

// 处理工具调用
server.setRequestHandler(CallToolRequestSchema, async (request) => {
    const { name, arguments: args } = request.params;
    
    if (name === "get_weather") {
        const weatherData: Record = {
            "北京": "晴, 25°C",
            "上海": "多云, 28°C",
        };
        return {
            content: [{
                type: "text",
                text: weatherData[args.city] || "未知城市"
            }]
        };
    }
    
    throw new Error(`Tool not found: ${name}`);
});

3.3 注册资源

TypeScript（注册资源）
// 注册资源列表
server.setRequestHandler(ListResourcesRequestSchema, async () => {
    return {
        resources: [{
            uri: "file:///docs/guide.md",
            name: "用户指南",
            description: "MCP 用户使用指南",
            mimeType: "text/markdown"
        }]
    };
});

// 处理资源读取
server.setRequestHandler(ReadResourceRequestSchema, async (request) => {
    const { uri } = request.params;
    
    if (uri === "file:///docs/guide.md") {
        return {
            contents: [{
                uri,
                mimeType: "text/markdown",
                text: "# MCP 用户指南\n欢迎使用..."
            }]
        };
    }
    
    throw new Error(`Resource not found: ${uri}`);
});

四、实战：天气服务 Server

下面我们通过一个完整的实战项目，演示如何使用 Python SDK 开发一个天气服务 MCP Server。这个 Server 提供了天气查询、天气预报和空气质量查询三个工具，以及用户指南和天气数据两个资源，还有天气报告和代码审查两个 Prompt 模板。

天气服务 Server 的设计考虑了实际应用场景的需求。工具方面，get_weather 提供实时天气查询，get_forecast 提供未来几天的天气预报，get_air_quality 提供空气质量指数查询。这三个工具覆盖了用户日常天气查询的主要需求。资源方面，用户指南提供了 Server 的使用说明，天气数据提供了城市列表和数据来源信息。Prompt 方面，天气报告 Prompt 帮助 LLM 生成格式化的天气报告，代码审查 Prompt 提供了代码审查的标准化模板。

4.2 Server 核心代码

Python（Server 核心实现）
from mcp.server import Server
from mcp.server.stdio import stdio_server
import asyncio

# 创建 Server
server = Server("weather-server")

@server.tool()
def get_weather(city: str) -> str:
    """获取天气"""
    return f"{city}: 晴, 25°C"

@server.tool()
def get_forecast(city: str, days: int = 3) -> str:
    """获取预报"""
    return f"{city} 未来{days}天: 晴转多云"

@server.resource(uri="file:///data/weather.json")
def read_data() -> str:
    """读取数据"""
    return '{"cities": ["北京", "上海", "广州"]}'

async def main():
    async with stdio_server() as streams:
        await server.run(
            streams[0], streams[1],
            server.create_initialization_options()
        )

if __name__ == "__main__":
    asyncio.run(main())

五、最佳实践

在开发 MCP Server 时，遵循以下最佳实践可以显著提高代码质量和可维护性。这些实践是基于实际项目经验总结的，涵盖了工具设计、错误处理、安全性、性能优化等多个方面。

首先，工具设计应该遵循单一职责原则。每个工具应该只完成一个明确的功能，避免工具功能过于复杂。工具名称应该使用动词加名词的格式（如 get_weather、search_users），使客户端能够直观理解工具的功能。工具描述应该简洁明了地说明工具的功能、使用场景和注意事项。

其次，错误处理是 Server 开发的重要环节。工具执行过程中可能遇到各种异常情况，如参数错误、网络超时、服务不可用等。Server 应该为每个工具定义清晰的错误处理逻辑，返回结构化的错误信息，帮助客户端和 LLM 理解失败原因并采取相应的恢复措施。

第三，安全性考虑不容忽视。Server 应该对输入参数进行严格验证，防止恶意输入导致的安全问题。对于涉及敏感操作的工具（如文件写入、数据库修改），应该实施权限控制和操作审计。同时，Server 不应该暴露内部实现细节，如文件路径、数据库连接串等敏感信息。

实战建议

在开发 MCP Server 时，建议先使用 Python SDK 进行原型开发，因为它提供了更简洁的装饰器接口和更快的开发速度。当 Server 功能稳定后，如果需要类型安全和更好的工程化支持，可以考虑迁移到 TypeScript SDK。同时，建议为 Server 编写单元测试，确保工具、资源和 Prompts 的功能正确性。

六、小结

MCP Server 开发是 MCP 协议实践的核心环节。通过 Python 和 TypeScript 两种 SDK，开发者可以用熟悉的语言快速构建 MCP 服务。Python SDK 提供了简洁的装饰器接口，使得工具、资源和 Prompts 的注册变得极其简单。TypeScript SDK 提供了类型安全的开发体验，特别适合需要严格类型检查的大型项目。无论使用哪种语言，核心开发流程都是一致的：创建 Server 实例、注册能力、实现业务逻辑、启动服务。

在实际开发中，建议遵循单一职责、清晰命名、错误处理、参数验证、超时控制和日志记录等最佳实践。这些实践不仅提高了代码质量，也使得 Server 更加可靠和易于维护。同时，建议为 Server 编写单元测试，确保工具、资源和 Prompts 的功能正确性。
