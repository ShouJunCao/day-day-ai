9.4 MCP Client 集成与多 Server 编排

模块九：MCP 协议 预计学习：60 分钟

学习目标

  • 掌握 MCP Client 的集成方法和连接管理
  • 学会连接和管理多个 MCP Server
  • 理解多 Server 编排的原理和实现
  • 能够设计复杂的多 Server 工作流

一、MCP Client 集成概述

MCP Client 集成是指将 MCP 客户端能力嵌入到 AI 应用中，使其能够连接和使用 MCP Server 提供的工具、资源和 Prompts。在实际应用中，一个 AI 应用通常需要连接多个 MCP Server，每个 Server 提供不同的能力。例如，一个 AI 助手可能需要同时连接天气服务（获取天气数据）、数据库服务（查询用户信息）、文件服务（读写文件）等多个 Server。

MCP Client 集成的核心价值在于：通过统一的协议接口，AI 应用可以动态发现和调用外部能力，而不需要为每个数据源或工具编写专用的集成代码。这种设计使得 AI 应用的能力扩展变得简单和灵活，新的能力只需要通过 MCP Server 暴露，就可以被现有的 AI 应用自动发现和使用。

Client 集成需要考虑的关键问题包括：连接管理（建立和断开与 Server 的连接）、能力发现（发现 Server 支持的工具、资源和 Prompts）、工具调用（将 LLM 的工具调用请求转发给对应的 Server）、结果整合（将 Server 返回的结果注入到 LLM 的上下文中）。

二、Client 连接管理

Client 连接管理是 MCP Client 集成的基础功能。Client 需要管理与多个 Server 的连接，包括建立连接、维护连接状态、处理连接异常、断开连接等。每个 Server 连接都是独立的，Client 需要为每个连接维护独立的状态信息，包括 Server 能力、工具列表、资源列表等。这种独立连接设计使得 Client 可以灵活地添加或移除 Server，而不影响其他连接。

连接管理的设计需要考虑可靠性和效率。对于本地 Server（通过 stdio 通信），Client 需要管理子进程的生命周期；对于远程 Server（通过 SSE 或 HTTP 通信），Client 需要管理网络连接和重试逻辑。当 Server 连接断开时，Client 应该能够自动重连或通知用户。在实际生产环境中，连接管理还需要考虑连接池、负载均衡、故障转移等高级特性。

2.1 连接管理实现

Python（Client 连接管理）
class MCPClient:
    """MCP Client SDK 核心类"""
    
    def __init__(self, name: str, version: str):
        self.name = name
        self.version = version
        self.servers = {}  # 管理多个 Server 连接
        self.connected = False

    def connect_server(self, server_name, server_info):
        """连接到一个 MCP Server"""
        conn = MCPServerConnection(server_name, server_info)
        self.servers[server_name] = conn
        conn.connect()  # 建立连接并发现能力
        self.connected = True

    def disconnect_server(self, server_name):
        """断开与指定 Server 的连接"""
        if server_name in self.servers:
            self.servers[server_name].disconnect()
            del self.servers[server_name]
        if not self.servers:
            self.connected = False

    def get_capabilities(self):
        """获取所有 Server 的能力摘要"""
        caps = {}
        for name, conn in self.servers.items():
            caps[name] = {
                "tools": len(conn.tools),
                "resources": len(conn.resources),
                "prompts": len(conn.prompts),
            }
        return caps

三、能力发现

能力发现是指 Client 在连接到 Server 后，获取 Server 支持的工具、资源和 Prompts 列表的过程。能力发现通常在连接建立时自动完成，Client 会缓存 Server 的能力信息，避免每次调用时都需要重新发现。这种缓存策略可以显著提高性能，减少网络通信开销。

在连接多个 Server 的场景中，Client 需要聚合所有 Server 的能力信息，形成一个全局的能力视图。这使得 LLM 可以看到所有可用的工具，而不需要关心它们来自哪个 Server。当 LLM 决定调用某个工具时，Client 需要根据工具名称找到对应的 Server，并将调用请求转发给该 Server。为了实现这一点，每个工具在聚合时都需要标记其来源 Server，方便后续的路由和调用。

3.1 能力发现实现

Python（能力发现）
def list_all_tools(self):
    """列出所有 Server 的工具"""
    all_tools = []
    for name, conn in self.servers.items():
        tools = conn.list_tools()
        for tool in tools:
            tool['_server'] = name  # 标记来源 Server
        all_tools.extend(tools)
    return all_tools

def list_all_resources(self):
    """列出所有 Server 的资源"""
    all_resources = []
    for name, conn in self.servers.items():
        resources = conn.list_resources()
        for res in resources:
            res['_server'] = name
        all_resources.extend(resources)
    return all_resources

def list_all_prompts(self):
    """列出所有 Server 的 Prompts"""
    all_prompts = []
    for name, conn in self.servers.items():
        prompts = conn.list_prompts()
        for prompt in prompts:
            prompt['_server'] = name
        all_prompts.extend(prompts)
    return all_prompts

四、工具调用与结果整合

工具调用是 MCP Client 最核心的功能。当 LLM 决定调用某个工具时，Client 需要拦截这个调用请求，找到对应的 Server，将请求转发给该 Server，等待 Server 返回结果，然后将结果注入到 LLM 的对话历史中。这个过程需要精确的消息管理和状态跟踪，确保对话的连贯性和一致性。在任何一步出现错误时，Client 都应该能够妥善处理，而不是让整个流程崩溃。

结果整合是工具调用的关键环节。Server 返回的结果需要转换为 LLM 可以理解的格式，然后注入到对话历史中。对于成功的工具调用，结果内容会作为工具响应返回给 LLM；对于失败的工具调用，错误信息也会返回给 LLM，让它能够采取相应的恢复措施。在实际应用中，结果整合还需要考虑上下文窗口限制，当结果过大时，需要进行截断或摘要处理。

4.1 工具调用实现

Python（工具调用与结果整合）
def call_tool(self, server_name, tool_name, arguments):
    """调用指定 Server 的工具"""
    if server_name not in self.servers:
        return {"error": f"Server not found: {server_name}"}
    return self.servers[server_name].call_tool(tool_name, arguments)

五、多 Server 编排

多 Server 编排是指在一个 AI 应用中同时管理多个 MCP Server，并协调它们之间的交互。编排器（Orchestrator）负责工具发现、工作流执行和结果整合。通过编排器，AI 应用可以执行复杂的多步骤任务，每个步骤可能涉及不同的 Server。这种编排能力使得 AI 应用能够像人类一样，协调多个数据源和服务来完成复杂的任务。

编排器的核心功能包括：工具发现（在所有 Server 中查找特定工具）、工作流执行（按顺序执行多个工具调用，支持参数传递）、错误处理（当某个步骤失败时的恢复策略）、上下文管理（在步骤之间传递数据）。

5.1 编排器实现

Python（多 Server 编排器）
class MCPOrchestrator:
    """MCP 多 Server 编排器"""
    
    def __init__(self, client):
        self.client = client

    def find_tool(self, tool_name):
        """在所有 Server 中查找工具"""
        for name, conn in self.client.servers.items():
            if tool_name in conn.tools:
                return {"server": name, "tool": conn.tools[tool_name]}
        return None

    def execute_workflow(self, steps):
        """执行工作流（多步骤工具调用）"""
        results = []
        context = {}
        
        for step in steps:
            server = step.get("server", "")
            tool = step.get("tool", "")
            args = step.get("arguments", {})
            
            # 支持从上下文中获取参数
            resolved_args = {}
            for key, value in args.items():
                if isinstance(value, str) and value.startswith("{{"):
                    var_name = value[2:-2]
                    resolved_args[key] = context.get(var_name, value)
                else:
                    resolved_args[key] = value
            
            result = self.client.call_tool(server, tool, resolved_args)
            results.append({"step": step, "result": result})
            
            # 将结果存入上下文
            context[f"result_{len(results)}"] = result
        
        return results

workflow = [

六、最佳实践

在集成 MCP Client 和管理多个 Server 时，遵循以下最佳实践可以显著提高系统的稳定性和可维护性。这些实践涵盖了连接管理、能力发现、工具调用、工作流编排等多个方面，是实际项目经验的重要总结。

首先，连接管理应该支持自动重连和超时处理。当 Server 连接断开时，Client 应该能够自动尝试重连，并在重连失败时通知用户。对于长时间运行的连接，应该设置心跳机制，定期检测连接状态。自动重连策略应该采用指数退避算法，避免在 Server 故障时造成雪崩效应。

其次，能力发现应该在连接建立时完成，并缓存结果。当 Server 能力发生变化时（如新增工具），Client 应该能够动态更新缓存。这可以通过订阅 Server 的能力变更通知来实现。

第三，工具调用应该有超时限制和错误处理。当工具调用超时时，Client 应该能够返回友好的错误信息，而不是让 LLM 无限等待。对于失败的工具调用，应该返回结构化的错误信息，帮助 LLM 理解失败原因。

最佳实践说明示例
自动重连连接断开时自动重连最大重试 3 次，间隔递增
能力缓存缓存 Server 能力信息连接时缓存，变更时更新
超时控制工具调用设置超时默认 30 秒超时
错误处理返回结构化错误信息{"error": "...", "code": 500}
日志记录记录连接和调用日志便于调试和性能分析
安全控制验证 Server 身份使用 TLS 加密通信
实战建议

在实际项目中，建议将 MCP Client 集成封装为一个独立的模块，与 AI 应用的核心逻辑分离。这样可以方便地更换或升级 MCP Client 实现，而不影响 AI 应用的其他部分。同时，建议为 Client 编写单元测试，模拟 Server 的响应，确保集成逻辑的正确性。

七、小结

MCP Client 集成与多 Server 编排是 MCP 协议实践的重要环节。通过 Client 集成，AI 应用可以动态发现和调用外部能力，而不需要为每个数据源或工具编写专用的集成代码。多 Server 编排使得 AI 应用可以执行复杂的多步骤任务，每个步骤可能涉及不同的 Server。这种编排能力大大扩展了 AI 应用的能力边界。

理解 Client 集成和多 Server 编排的原理和实现，是构建强大 AI 应用的关键。在实际项目中，建议遵循自动重连、能力缓存、超时控制、错误处理和日志记录等最佳实践，确保系统的稳定性和可维护性。在下一节 9.5 中，我们将深入探讨 MCP 与 Function Calling 的关系与差异，理解两种技术如何互补协作，共同构建完整的 AI 工具调用生态。
