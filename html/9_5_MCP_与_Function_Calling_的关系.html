9.5 MCP 与 Function Calling 的关系与差异

模块九：MCP 协议 预计学习：45 分钟

学习目标

  • 理解 MCP 与 Function Calling 的本质区别
  • 掌握 MCP 工具如何适配 Function Calling 格式
  • 了解两种技术如何互补协作
  • 能够在实际项目中正确选择和使用两种技术

一、核心概念回顾

在深入学习 MCP 与 Function Calling 的关系之前，我们先回顾一下两种技术的核心概念。Function Calling 是 LLM 提供商（如 OpenAI、Anthropic、Qwen）提供的一种能力，允许模型在生成回答的过程中调用外部工具。它关注的是模型如何"知道"有哪些工具可用、如何"决定"调用哪个工具、以及如何"理解"工具返回的结果。Function Calling 的核心在于模型的决策能力。

MCP（Model Context Protocol）是一个开放的协议标准，用于标准化 AI 应用与外部数据源和工具之间的集成方式。它关注的是如何"连接"AI 应用与外部系统、如何"发现"可用的工具、以及如何"传输"数据。MCP 的核心在于协议层的标准化和互操作性。

简单来说，Function Calling 解决的是"模型如何智能地使用工具"的问题，而 MCP 解决的是"工具如何标准化地暴露给模型"的问题。两者解决的是不同层面的问题，但在实际应用中是紧密协作的。

二、MCP 工具如何适配 Function Calling

MCP 工具与 Function Calling 工具在格式上有一定的差异，但通过适配器模式，可以方便地将 MCP 工具转换为 Function Calling 格式。这种转换使得 MCP 工具可以被任何支持 Function Calling 的 LLM 使用，而不需要为每个 LLM 单独实现工具定义。

适配的核心思路是：将 MCP 工具的定义格式（name、description、inputSchema）转换为 Function Calling 所需的格式（type、function、parameters）。MCP 的 inputSchema 本身就是基于 JSON Schema 的，与 OpenAI Function Calling 的参数格式高度兼容，这使得转换过程变得简单直接。

2.1 适配代码实现

Python（MCP 到 FC 适配器）
class MCPToFCAdapter:
    """MCP 到 Function Calling 适配器"""
    
    def __init__(self):
        self.tools = []
        self._handlers = {}

    def register_tool(self, tool, handler):
        """注册 MCP 工具及其处理函数"""
        self.tools.append(tool)
        self._handlers[tool.name] = handler

    def get_fc_tools(self):
        """获取所有工具的 FC 格式"""
        return [tool.to_fc_format() for tool in self.tools]

    def execute_tool_call(self, tool_call):
        """执行工具调用并返回 FC 消息格式"""
        function = tool_call.get("function", {})
        name = function.get("name")
        arguments = json.loads(function.get("arguments", "{}"))
        
        if name in self._handlers:
            result = self._handlers[name](**arguments)
            return FCMessage(
                role="tool", name=name,
                tool_call_id=tool_call.get("id"),
                content=str(result)
            )
        return FCMessage(role="tool", content=f"Error: Tool {name} not found")

三、两者的本质差异

理解 MCP 与 Function Calling 的本质差异，是正确选择和使用两种技术的关键。Function Calling 是 LLM 模型的内置能力，由模型提供商定义和实现，不同厂商的实现可能有细微差异。MCP 是一个开放的协议标准，由社区推动，旨在实现跨厂商的互操作性。

从架构层面来看，Function Calling 关注的是模型与工具之间的交互逻辑，即模型如何决定调用哪个工具、如何生成参数、如何理解结果。而 MCP 关注的是应用与外部系统之间的连接方式，即如何发现工具、如何传输数据、如何管理连接。Function Calling 是"智能层"的能力，MCP 是"基础设施层"的协议。

在实际应用中，两者是互补的关系。MCP 提供了标准化的工具暴露方式，使得任何支持 MCP 的客户端都可以发现和调用工具。Function Calling 提供了模型的工具调用能力，使得 LLM 可以智能地选择和使用工具。将两者结合使用，可以实现最强大的 AI 工具调用体验。

四、协作模式

MCP 与 Function Calling 的协作模式可以分为三个阶段：工具发现阶段、工具调用阶段和结果整合阶段。在工具发现阶段，MCP Client 通过 MCP 协议从 Server 发现可用工具，然后将工具列表转换为 Function Calling 格式，发送给 LLM。在工具调用阶段，LLM 决定调用哪个工具并生成参数，Client 将调用请求通过 MCP 协议转发给 Server，Server 执行工具并返回结果。在结果整合阶段，Client 将 Server 返回的结果转换为 Function Calling 消息格式，注入到 LLM 的对话历史中。

这种协作模式的优势在于：MCP 负责标准化的工具暴露和数据传输，Function Calling 负责智能的工具选择和参数生成。两者各司其职，共同构建了完整的 AI 工具调用体验。在实际项目中，开发者只需要编写一次 MCP Server，就可以被任何支持 Function Calling 的 LLM 使用，实现了真正的"一次编写，到处使用"。

五、技术选型建议

在实际项目中，MCP 和 Function Calling 不是二选一的关系，而是应该结合使用。MCP 提供了标准化的工具暴露方式，使得工具可以被多个 AI 应用共享。Function Calling 提供了模型的工具调用能力，使得 LLM 可以智能地选择和使用工具。

如果你的项目只需要与单一厂商的 LLM 集成，可以直接使用该厂商的 Function Calling API，而不需要引入 MCP。但如果你的项目需要支持多个 LLM 厂商，或者需要将工具暴露给多个 AI 应用，那么引入 MCP 是更好的选择。MCP 可以作为 Function Calling 的基础设施层，为多个 AI 应用提供统一的工具暴露接口。

核心理解

MCP 和 Function Calling 解决的是不同层面的问题。MCP 是"连接协议"（如何连接 AI 与外部系统），Function Calling 是"调用机制"（模型如何决定调用哪个工具）。两者互补而非竞争。在实际项目中，MCP 负责暴露和管理工具，Function Calling 负责让模型智能地选择和使用这些工具。将两者结合使用，可以构建最强大的 AI 工具调用系统。

六、小结

MCP 与 Function Calling 的关系可以概括为：MCP 是基础设施，Function Calling 是使用方式。MCP 提供了标准化的工具暴露和数据传输方式，使得工具可以被多个 AI 应用共享。Function Calling 提供了模型的工具调用能力，使得 LLM 可以智能地选择和使用工具。两者结合使用，可以构建完整的 AI 工具调用生态。
