9.6 MCP 传输层（stdio、SSE、HTTP Streaming）

模块九：MCP 协议 预计学习：50 分钟

学习目标

  • 理解 MCP 三种传输层的核心差异
  • 掌握 stdio 传输层的工作原理和实现
  • 了解 SSE 和 HTTP Streaming 传输层的特点
  • 能够根据实际需求选择合适的传输层

一、传输层概述

MCP 协议支持三种传输层：stdio（标准输入输出）、SSE（Server-Sent Events）和 HTTP Streaming（流式 HTTP）。传输层负责在客户端和服务器之间传输 JSON-RPC 2.0 消息。选择合适的传输层取决于应用场景：本地工具调用通常使用 stdio，远程服务调用使用 SSE 或 HTTP Streaming。

传输层的设计需要考虑几个关键因素：通信方向（单向或双向）、连接方式（进程通信或网络通信）、数据格式（行分隔 JSON 或事件流）、以及安全性（本地通信无需加密，远程通信需要 TLS）。MCP 协议抽象了传输层的差异，使得上层的应用逻辑可以在不同传输层之间无缝切换。

在实际项目中，传输层的选择直接影响系统的部署方式和性能表现。stdio 传输层因为不需要网络配置，是本地开发和调试的最佳选择；SSE 传输层因为兼容性广泛，是远程部署的稳妥选择；HTTP Streaming 传输层因为架构简洁，是未来发展的主流方向。理解三种传输层的特点和差异，是正确部署 MCP 服务的基础。

1.1 传输层架构

二、stdio 传输层

stdio 是 MCP 最简单的传输层，基于标准输入（stdin）和标准输出（stdout）。客户端将 MCP Server 作为子进程启动，通过 stdin 发送 JSON-RPC 请求，通过 stdout 读取响应。这种传输方式不需要网络配置，简单高效，是本地工具调用的首选。

stdio 传输层的核心特点：消息以换行符分隔的 JSON 格式传输，每行一条完整的 JSON-RPC 消息；stdout 用于发送响应，stderr 用于输出日志和调试信息（stderr 不会被解析为协议消息）；连接建立即开始通信，无需握手过程。

在实际应用中，stdio 传输层是最常用的传输方式，特别是在 AI 编辑器（如 Cursor、Claude Desktop）调用本地 MCP Server 的场景中。编辑器将 Server 作为子进程启动，通过 stdin 发送用户请求，通过 stdout 读取 Server 响应。这种方式的优点是启动速度快、无需端口配置、安全性高（因为是本地进程通信）。

2.1 stdio 实现

Python（stdio 传输层）
import json
import sys
import asyncio

class StdioTransport:
    """stdio 传输层"""
    
    async def connect(self):
        """stdio 连接即时可用"""
        self.connected = True
    
    async def send(self, message):
        """发送消息到 stdout（换行分隔 JSON）"""
        json_str = json.dumps(message, ensure_ascii=False) + "\n"
        sys.stdout.write(json_str)
        await sys.stdout.flush()
    
    async def receive(self):
        """从 stdin 读取消息"""
        line = sys.stdin.readline()
        if not line:
            raise EOFError("End of input")
        return json.loads(line.strip())

# Server 端：监听 stdin，处理请求，写入 stdout
# Client 端：启动 Server 子进程，通过 stdin 发送，通过 stdout 接收

三、SSE 传输层

SSE（Server-Sent Events）是 MCP 早期版本的主要远程传输层。它基于 HTTP 的 SSE 协议，允许服务器向客户端推送事件流。SSE 传输层需要两个端点：一个 GET 端点用于建立 SSE 长连接（接收服务器消息），一个 POST 端点用于发送请求给服务器。

SSE 的工作流程：客户端首先通过 GET 请求连接到 /sse 端点，服务器返回一个 SSE 事件流，包含一个特殊的 "endpoint" 事件，告知客户端 POST 请求的目标地址。随后，客户端通过 POST 请求将 JSON-RPC 消息发送到指定端点，服务器处理后将响应通过 SSE 事件流返回给客户端。

3.1 SSE 实现

Python（SSE 传输层）
class SSETransport:
    """SSE 传输层"""
    
    def __init__(self, server_url):
        self.server_url = server_url
        self.endpoint_url = ""
    
    async def connect(self):
        """建立 SSE 连接"""
        # 1. GET /sse 建立长连接

四、HTTP Streaming 传输层

HTTP Streaming 是 MCP 最新的传输标准，旨在简化远程通信。与 SSE 需要两个端点不同，HTTP Streaming 只需要一个端点即可完成双向通信。客户端通过 POST 请求发送消息，服务器通过 HTTP 响应流（Chunked Encoding）或 Server-Sent Events 返回响应。

HTTP Streaming 的优势在于简化了客户端实现：只需要一个 HTTP 端点，不需要管理两个独立的连接；支持双向流式传输，服务器可以在处理过程中实时返回部分结果；更好的代理兼容性，因为使用的是标准的 HTTP POST 请求。

4.1 HTTP Streaming 实现

Python（HTTP Streaming 传输层）
class HTTPTransport:
    """HTTP Streaming 传输层"""
    
    def __init__(self, server_url):
        self.server_url = server_url
    
    async def send(self, message):
        """发送 HTTP 请求"""
        async with httpx.AsyncClient() as client:
            async with client.stream(
                "POST", self.server_url,
                json=message,
                timeout=None  # 流式传输需要无限超时
            ) as response:
                async for chunk in response.aiter_text():
                    # 解析 Chunked Encoding 中的 JSON-RPC 响应
                    yield json.loads(chunk)

五、传输层选型建议

选择合适的传输层是 MCP 集成的关键决策之一。以下是具体的选型建议：

如果你需要在本地调用 AI 工具（如通过 Cursor、Claude Desktop 调用本地 Python 脚本），stdio 是最简单高效的选择。它不需要配置网络端口，启动即用，适合开发和测试阶段。如果你的 Server 需要部署到远程服务器上，并且客户端通过网络访问，那么应该选择 HTTP Streaming 或 SSE。HTTP Streaming 是最新的标准，推荐使用；SSE 适合需要兼容旧版 MCP 客户端的场景。

在实际项目中，建议 Server 同时支持多种传输层，以便客户端可以根据实际需求选择最合适的方式。MCP Python SDK 和 TypeScript SDK 都提供了对多种传输层的支持，开发者只需要在启动 Server 时指定传输类型即可。

实战建议

在开发 MCP Server 时，建议优先实现 stdio 传输层，因为它最简单，便于本地开发和调试。当需要部署到远程环境时，再添加 HTTP Streaming 或 SSE 支持。同时，建议为 Server 添加传输层自动检测功能，根据运行环境自动选择最合适的传输方式。

六、小结

MCP 协议支持三种传输层：stdio、SSE 和 HTTP Streaming。stdio 适用于本地进程通信，简单高效；SSE 适用于远程通信，兼容性好但需要两个端点；HTTP Streaming 是最新的标准，只需一个端点即可完成双向通信。理解不同传输层的特点和适用场景，是正确部署 MCP 服务的关键。
